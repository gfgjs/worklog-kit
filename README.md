# worklog-kit

让 Agent 跨会话接着干活的最小约定：需要记住的信息写进项目里的普通 Markdown 文件，下次开会话时直接读。

## 怎么用

- 把 `skills/worklog/` 整个目录复制到你所用的 Agent 支持的 Skill 位置；也可以直接读取 [skills/worklog/SKILL.md](skills/worklog/SKILL.md) 的内容。
- 任何能读写项目文件的 Agent 都能执行 Skill 里的说明：没有 Skill 加载机制时，把它作为任务说明给出即可。
- 完整交付就是这份说明、一个 Skill 和一份许可，没有 CLI、配置文件、运行时或后台服务。

## 一次普通任务的样子

**开始**：目标只有一件事——给笔记加上按标题搜索。项目里没有上下文文件，Agent 读当前代码后直接工作，无需预建上下文文件。

**有值得记住的东西时**：写到一半发现组合输入会提前触发筛选，于是项目根目录出现一份 `CONTEXT.md`：

```markdown
# 项目上下文

## 未完成任务

### 标题搜索

目标：支持按标题筛选笔记，保留原有排序。
当前：过滤逻辑和空结果提示已完成，已有测试通过；键盘操作未验证。
决定：先做子串匹配，因为本轮只要求标题查找；暂不做全文索引。
下一步：在 src/search.js 修复组合输入，再验证中文输入与上下键选择。
```

**下次继续**：新会话读这份文件，按线索核实当前项目后继续，不必翻上一轮对话。

## 边界

- 项目文档：给人和后续开发者的说明、规范、交付物，按项目需要维护，该更新就更新原文。
- 项目上下文：文档和代码里恢复不出来、后续仍然需要的信息，按需放进一份 `CONTEXT.md`，只保留「长期有效」和「未完成任务」两类内容，没有的一类省略。
- 没有值得保留的信息时，不额外创建上下文文件。
- 任务完成后删掉对应小节；不归档、不做完成台账。
- 自动加载取决于所用 Agent 是否支持：Skill 只在被使用时生效，不做后台注入。
