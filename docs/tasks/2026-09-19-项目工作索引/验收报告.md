## 事项流转(场景 5)

在独立临时夹具演练,每次转换后 `check docs` 通过:

- **未立项**:候选在主题开放事项,todo 当前重点指主题锚点,可发现可定位。
- **立项**:同一锚点改指任务 state,主题不复述;todo 条目可保持指锚点。
- **部分承接(A/B)**:A 完成后成果写入主题当前现状(证据引用指 A details#执行结果),开放条目保留剩余范围+启动条件+指向 B;A 的 todo 条目撤下,B 保留;相关任务撤 A 留 B。
- **全部解决(指任务 state 条目)**:B 完成,整个开放条目删除,成果+验证边界进现状,todo 条目撤下。
- **全部解决(指主题锚点条目)**:打包体积立项(条目保持指锚点)后完成,条目撤下、不改指结果页;当前重点空后写「无」;有导航价值的主题入口保留。
- **明确放弃(指任务 state 条目)**:条目撤下,主题依据与约定留一句结论,任务以「已取消」留档。
- **暂停**:开放事项保留并写明再启动条件,todo 条目保留指向可继续任务。
- **取消**:承接任务取消但问题保留,开放事项+再启动条件可回找,条目移入其他事项指主题;显式用目录全名查看已取消任务返回 0。
- **负例**:任务验收范围内未完成的内容(移动端验证)未移回主题制造完成;现状明确写「尚未建立/未验证」。
