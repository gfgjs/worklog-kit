# 迁移说明：从旧八项单元到四组单元材料

本文件说明如何把已有的任务记录迁到本轮确认的任务记录规范（单元四组材料）。迁移只调整布局与归属，不追认新的验收，也不改写历史结论；目标是让同一份任务文件既能接续又不再随轮次膨胀。当前只迁移本仓库；外部项目按本文人工处理。

## 旧八项到四组单元的完整映射

| 旧三级标题 | 归属 | 说明 |
|---|---|---|
| 目标与验收 | **目标与验收** | 原样保留。 |
| 最低验证 | **目标与验收** | 它是计划与通过条件，不是结果；并入目标与验收，未运行的检查仍写成待办条件，不得当作事实。 |
| 修改范围 | **方案与范围** | 与实现路径合并。 |
| 实现路径 | **方案与范围** | 单元内的实现选择与边界；被并入的单元范围说明保留原意。 |
| 回交条件 | **方案与范围** | 只保留单元特有的偏差条件；通用回交规则归角色说明。 |
| 依赖与前提 | **依赖与必读** | 单元前提。 |
| 必读材料 | **依赖与必读** | 单元专属必读；共享必读留在公共章节。 |
| 回传要求 | 角色说明 | 通用回传规则归角色说明，不再逐单元填写；单元确有额外回传要求时写进「方案与范围」。 |

details 全局「执行结果」中属于某单元的行，并入该单元 **当前结果**；当前结果只承接真实已执行的结论、适用版本或环境、证据与未验证项，不含计划性的验证条件。取消全局「执行结果」章节。

## 人工迁移步骤

1. 按上表把每个旧单元的八个三级标题合并成四组：目标与验收（含最低验证的计划条件）、方案与范围（修改范围、实现路径与单元特有回交条件）、依赖与必读（依赖与前提、必读材料）、当前结果。正文按映射搬运，不重写结论。
2. 把 details 全局「执行结果」里属于该单元的真实结果行移入该单元「当前结果」；更新既有结论而不是追加，保留版本、样本与可比条件。计划性的验证仍留在「目标与验收」。
3. 旧结果中确需保留的长历史、每轮失败证据与原始输出，移到任务内 `references/`（或就近的已有报告），在原位置留一句摘要与普通链接。当前缺口在「当前结果」里留指针。
4. 删除已无内容的全局「执行结果」章节，不保留空的旧字段。
5. 更新 `state.md`：进度表只留状态与结果指针，「下一步与阅读」清掉过时必读，指向 details 对应单元。
6. 修复受影响的活链接：单元锚点、必读目标与跨文件引用改指新位置；指向已删除「执行结果」的链接改指对应单元的「当前结果」或 references。
7. 用本轮源码的 `check` 核对结构、锚点与单元指向；没有匹配工具时，用文件能力按[使用说明](usage.md#格式规范)逐条核对。再按角色提取一次，确认普通历史链接没有被误标为必读而整段注入。

迁移只做布局与归属调整：历史证据保留、活链接可达，「已自检 / 已完成」等原状态与验收结论不变，不因迁移改写为通过。已完成任务同样迁移，仅调整布局并保留原状态。

## 单一现行规范

迁移后本仓库只有一套现行格式，不保留并行的旧八项正文或永久兼容分支。旧任务目录、旧报告与历史材料仍是可读的普通 Markdown，作为历史保留，不再作为执行依据。外部项目沿用旧格式的记录按本文人工迁移；在迁移完成前，旧记录仍可按其原有章节手工读取。

专门的迁移与一致性核对由整体验收负责，见[任务记录](tasks/2026-09-22-精简记录与接续/state.md)。
