# 产品流程、附带 Skill 与全仓代码精简方案

本轮只制定方案；仅修复了一处自检入口接线。下文的目标行为、命令设计和 Skill 草案均未实施，不代表当前产品已经支持。

## 1. 建议结论

优先精简使用者的任务，再精简实现：让日常流程只需要「开始 → 记录/接续 → 收口」，让 CLI 承担目录、模板、编号、状态和检查，让 Skill 只说明什么时候记录、记录什么、什么值得沉淀。

建议分两步：先在现有三件套模型上减少重复步骤和说明，保持旧数据可用；再补齐轻量任务的完整生命周期，评估让单文件成为新任务默认。不要现在只把 `start` 的默认值从 trio 改成 lite，也不要以“精简”为由直接删除迁移、回滚、路径保护或测试。

最优先的四项：

1. 单条 `check` 覆盖文档与索引校验；收口复用同一检查入口。
2. Skill 主体只保留任务选择、开工、接续、记录、收口五部分，把机械操作移交 CLI。
3. 收口自动准备机械可推导内容，只要求人或 agent 填写真正需要判断的去向与理由。
4. 初始化减少默认复制件；模板从包内读取，仓内只保存实际定制项。

## 2. 审查方法与实测基线

依据当前工作树中的入口、实现和真实运行结果判断，历史设计与 Review 仅作背景。覆盖 `bin/`、`src/`（含全部共享库）、`tools/`、`skills/`、`templates/`、`schema/`、`locales/`、包清单、CI 和仓库治理配置。产品生命周期、Skill/模板、治理/迁移分别独立审查，主审整合入口、测试和发布工具结论。

环境：Windows / PowerShell，Node 24.20.0，npm 11.19.0。未在本轮运行 Linux、Node 20/22 或远端 CI；配置了这些矩阵不等于本轮验证通过。消费流程在系统临时目录操作，调用当前源码的绝对路径 CLI，不使用注册表旧版。

工作开始时已有 `CLAUDE.md` 删除、`AGENTS.md` 新增，以及上一轮 Review 未跟踪改动，本轮未触碰这些变更。Git 的所有权限制使用单次命令配置绕过，不修改用户全局 Git 设置。`rg` 启动失败后改用 PowerShell 与 Node 检索。

| 实测项目 | 结果与边界 |
|---|---|
| `npm run check` | 初始通过，90 个文档、4 个代码/配置件；新报告加入后另行复验 |
| `node bin/worklog.mjs index check` | 通过 |
| `npm run skills` | exit 1，当前执行环境未安装个人 Skill；不是包内 Skill 校验失败，不为做绿而安装到用户目录 |
| 初次 `npm run selftest` | 17 套中 token-audit 和 release-selftest 失败；前者是缺入口，后者是 npm 缓存写权限 |
| 修复后 `npm run selftest` | 设置进程级临时 npm 缓存后，17 套全部通过，包含真包安装、e2e、迁移和故障回滚 |
| `node tools/release-selftest.mjs` | 临时缓存下通过：pack → 安装 tgz → init/start/note/checkpoint/resume/list/next-id/check/index/doctor |
| 全部 `.mjs` 语法检查 | 38 个文件通过 |
| `doctor` | exit 0，但报告个人 Skill 缺失、六件仓内副本缺失、两个待收口任务、一个任务体积超阈值；exit 0 不等于没有建议 |

| `--help` / `start --help` / `check --help` | 三者输出相同：36 行、2414 字符；当前没有命令专属帮助 |
| `npm pack --dry-run --json` | 当前包 51 个条目，解包 676169 bytes，压缩约 224 KB；未发布 |

源码量口径：38 个 `.mjs` 共 10473 行（按换行切分，含空行与末尾空项）；按内嵌 selftest 起点和测试文件粗分，约 3918 行属于测试区域。`check-docs.mjs` 1698 行中约 952 行、`upgrade.mjs` 1728 行中约 690 行处于 selftest 尾部。此为结构估算，不是精确逻辑代码量，也不是可删除量。

Skill 实际为 8843 bytes、4585 字符、72 行。不能以“只有 72 行”判断阅读负担：长行里包含多条规则。后续用正文字符量、强制动作数和真实任务读写次数验收，不宣称未经实测的 token 节省比例。

## 3. 产品流程如何收敛

### 3.1 入口：保留能力，减少首次暴露

当前有 17 个顶层命令（`src/lib/cliargs.mjs:10`），帮助、参数声明和调度分别维护。建议默认帮助展示四个日常命令 `start/resume/note/closeout`，另列 `list/check` 为查询与验证；初始化、安装、升级、诊断、baseline、team、编号和测试放到维护说明或完整帮助。

不需要为减少列表另造一套命令别名。旧命令保留兼容，先减少用户必须记住的命令数，再考虑废弃低价值入口。每个子命令帮助只说明本命令的参数、最短例子、失败后下一步。

把参数声明提升为解析后的结构结果（位置参数、取值参数、布尔参数），供调度使用；避免中央校验通过后每个命令再猜原始数组。帮助文案可复用这份参数元数据，但行为前置条件仍由业务层校验。

实测缺陷：`index --warn-only build` 被中央层接受，exit 0 却只执行索引检查；`index build --warn-only` 才生成文件。原因是 `bin/worklog.mjs:70` 只取 `args[0]`，而 `src/lib/cliargs.mjs:13` 允许位置参数出现在 flag 后。后续必须明确接受并正确解析，或明确拒绝这种组合，不能静默跑另一条路径。本轮记录，未扩大接线修复范围。

帮助还把 `--warn-only` 称为“全局”，实测 `start ... --warn-only` exit 2。应明确它只适用于校验类命令；不应为迎合文字而让写入命令支持忽略失败。

### 3.2 开始：降低建档成本

当前空仓 `init` 实际打印 24 条文件写入，包括配置、目录占位、CI、CODEOWNERS、Skill、五个模板、收口手册、manifest 和文档基础件。随后默认 `start` 进入三件套。单次工作已足够结束的任务不应被要求先建档。

短期保持 trio 默认，但把选择原则写清：只对跨会话、有持续状态的任务建档；小改动直接完成并报告。不要再用“工具调用达到某个次数”替代是否需要持久记忆的判断。

中期建议补齐现有 lite 的记录、接续、完成、归档能力后，再将其作为新任务默认；trio 留给确实需要分开计划、发现和历史的大任务，team 继续显式选择。旧任务按磁盘格式识别，不批量重写为新格式。默认翻转须单独发布并附兼容验证。

### 3.3 记录与接续：只维护一份当前状态

把“已知目标、当前进度、关键决定、未解决问题、下一步”作为接续所需内容。`resume` 默认返回这些当前信息；完整历史按需读取。Skill 不再同时规定固定行数读取、全量重读、逐次追加与定期扫描等多套策略。

`note` 负责选择落点、生成必要 ID 和维护表格形状；用户或 agent 提供事实与判断。普通进度不自动提升为候选，不让所有日志都承担处置表成本。`next-id` 可保留兼容，但不进入正常工作链。

`checkpoint` 作为需要压缩历史时的维护能力，保留原文归档；不要求每轮固定调用，也不丢弃未解决问题。自动化压缩只能搬移内容，不能替人决定哪些事实可以忘记。

### 3.4 收口：去掉准备表格的机械劳动

目标流程是：确认工作与验证结果 → 检查尚未处置的关键候选 → 执行收口。命令从任务中提取候选、生成待处理清单或草稿、检查去向和理由，然后完成状态翻转、迁移和索引登记。

机械推导可以自动填：日期、任务名、候选 ID、当前已登记处置、目录和文档状态。不能自动填：经验是否值得保留、是否与既有结论重复、未完成事项是否可取消、验证是否真实发生。缺判断项时返回具体缺项，不要求把整个手册重新阅读一遍。

建议在现有 `closeout` 上提供准备/预览能力，不另造收口命令族。预览和执行复用同一检查；预览不写入，用户明确要求导出草稿时才保存文件。无候选的轻量任务不强制制造七列表，但仍保留完成摘要、验证与遗留问题。涉及契约变化须同时调整门禁和模板，不能仅删 Skill 文字。

用户明确要求完成某项工作，且收口只是已授权的本地记录整理时，不额外索要固定口令。归档会导致数据丢失、需要替用户做未授权取舍或执行发布等动作时，才针对那项动作确认。候选处理仍不能伪造；“命令权限提示等于用户收口批准”的代码注释不应作为产品授权协议。

### 3.5 检查：一个日常入口

建议 `check` 汇总文档与索引检查，保留各检查模块作为可独立测试的实现。`index build` 只负责生成视图；旧 `index check` 继续作为兼容调用。CI 和收口共用聚合校验，不再要求使用者记住“双门”。

改变默认 `check` 语义会让以前遗漏索引错误的仓变红，因此要附升级说明、错误来源标识及 brownfield 行为验证，不能悄悄改变旧版本判定。非法配置仍 exit 2，违规仍 exit 1，warn-only 不得吞配置错误。

## 4. Skill 的精简原则

Skill 是 agent 的行为提示，不是第二份 CLI 实现或迁移手册。主体只回答：何时使用、怎么开始/恢复、何时记录、如何结束。具体格式由命令生成，需要人工处理的例外由错误信息按需指向参考说明。

| 当前职责 | 建议落点 | 原因 |
|---|---|---|
| 任务目录、日期、模板复制、frontmatter、候选编号 | CLI | 可机械执行，重复教授易漂移 |
| 选普通任务/轻量/复杂任务 | Skill 一小段 | 属任务判断，但不需要多套阈值 |
| 什么值得记录、什么值得提升 | Skill 核心 | 这是 agent 应承担的语义判断 |
| 固定读取方式、行数、重复扫描、表格字段教学 | 默认视图/按需帮助 | 应减少主上下文里的维护规则 |
| team 并发事件、迁移、配置枚举、特殊处置 | 按需参考 | 不让单人常规任务支付完整复杂度 |
| 备份、回滚、路径保护、检查 | CLI 与测试 | 删说明不能删实现保护 |

第一阶段目标：主 Skill 正文不超过约 2000 字符（验收预算，不是已达成收益），最多五个主要阶段；不内嵌完整模板和参数清单，不要求全仓查 ID、不要求每次固定重复读取、不要求额外形式化确认。进阶内容只有实际需要时加载，避免把原文简单搬到一个“必读参考”里造成假精简。

先发布与当前 CLI 能力一致的短版，再随 lite/自动编号/收口准备补齐而进一步压缩。不能提前写成当前命令不存在的理想流程。

## 5. 全仓代码与分发精简

| 范围 | 建议 | 保留的边界 |
|---|---|---|
| `bin/worklog.mjs`、`src/lib/cliargs.mjs`、`locales/zh.json` | 参数解析和帮助单源；错误只说原因、位置、下一步；历史 F/R/D 编号移出用户消息 | 未知参数拒绝、help 零写入、稳定退出码 |
| `src/tasks.mjs`、`src/closeout.mjs`、`src/team.mjs` | 生命周期共享任务识别和元数据；优先补齐 lite，再删除重复分支 | trio/team 老任务继续读取；事务回滚 |
| `src/init.mjs`、`src/install-skills.mjs`、`src/lib/templates.mjs` | 包内默认模板 + 仓内显式覆盖；新仓只复制实际需要的 Skill/定制模板；CI 安装变为明确选择 | 已有本地定制不覆盖；旧 manifest 能识别、迁移 |
| `src/check-docs.mjs`、`src/check-index.mjs`、`src/build-index.mjs`、`src/lib/docmeta.mjs` | 共享文档分类/解析结果和聚合检查；先统一外部入口，再评估内部扫描次数 | 历史快照、权威唯一、链接范围等不同语义不能硬并 |
| `src/upgrade.mjs`、`src/lib/config.mjs`、`schema/` | 当前配置与旧版迁移分层；逐版本迁移表清晰化 | v1–v6 仍是实际支持范围，不因当前最新版只有 v6 就删历史 schema |
| `src/lib/frontmatter.mjs`、`src/lib/jsoncedit.mjs`、`src/lib/schema.mjs` | 保持小型共享原语；只在调用语义相同时合并重复实现 | JSONC 注释保留、Markdown 围栏/转义、schema fail-closed；不为少行数贸然换库 |
| `src/doctor.mjs` | 结构化诊断结果统一，再渲染文字/JSON；区分产品错误、维护建议、缺少个人安装 | 缺安装不冒充损坏；建议不能伪装已执行修复 |
| 内嵌 selftest 与 `src/e2e.mjs` | 将测试布局整理到独立区域、常规命令按需加载；不是删测试 | 全量覆盖、真包冒烟和故障注入要继续可运行；包内 selftest 契约另行决定 |
| `tools/token-audit/` | 定位为维护者实验工具；修好实际测试接线；缺失 CLI 若要恢复应单独明确需求 | 估算器不是账单；固定历史 description 成本不能用作新 Skill 的真实省费结论 |
| `tools/sync-public.mjs`、`.sync-allowlist.json` | 与消费产品流程分开；评估留在维护源而非让消费者理解双源同步 | 不撤敏感词、symlink、越界、exact tgz 和 ff-only 保护；不在本轮同步或发布 |
| `tools/release-selftest.mjs`、CI | 保留唯一 tgz 安装链；避免普通校验重复 pack；维护测试入口集中 | 测试与发布必须同一 artifact；不把部署/发布并入任务收口 |
| README、模板、历史 docs | README 主体缩成最短入口与能力边界；历史审计不再混进产品操作提示 | 历史档案先保留链接可达，不因篇幅大批量删档 |

当前包较小，启动帮助的单次观测约 50ms；这不是稳定性能基准。懒加载与测试拆分是维护性改进，优先级低于减少人工步骤。不要为追求更小包体新建复杂插件系统、迁移 DSL 或模板注册框架。

## 6. 实施顺序与验收

| 批次 | 内容 | 必须通过的验收 |
|---|---|---|
| A：先减少理解成本 | 命令专属帮助、短版 Skill、简洁错误、参数一致性、清楚区分 doctor 输出 | 当前真实 trio 使用链可照说明完成；帮助不写盘；未知/缺值/顺序问题有覆盖 |
| B：减少重复操作 | 聚合 check、自动编号、closeout 准备清单、模板按需读取 | 无候选/有候选/无效去向/重复候选/归档失败均有真实消费仓用例；保护不降级 |
| C：减少默认流程 | 补齐 lite 生命周期，验证后调整新任务默认；旧 trio/team 不迁改 | lite 能开始、记录、恢复、完成、归档，check 与 list/resume 结果一致；旧任务仍全链通过 |
| D：整理维护代码 | 测试与运行代码分层、迁移分层、统一诊断与扫描上下文、维护工具隔离 | 既有 17 套测试、精确 tgz 安装链、Windows/Linux 与受支持 Node 矩阵通过 |

每批单独提交和评审，先跑与改动有关的检查，再跑三项仓库门禁。个人 Skill 检查用临时 home 构造“已安装”状态验证；不强制污染开发者主目录。若将其改为包内静态检查，应同时改脚本名称/说明，避免“skills”继续混淆两种检查。

验收同时记录：新仓写入文件数、常规任务所需命令数、手工修改文件数、Skill 主体字符数、恢复视图大小，以及两个代表任务中的实际读写调用。行数/估算 token 只作旁证，不预报未经 A/B 验证的收益百分比。

## 7. 本轮小修记录

问题：`src/selftest.mjs` 调用不存在的 `tools/token-audit.mjs --selftest`。当前仓库实际保留 `tools/token-audit/selftest.mjs` 及其依赖和 golden fixtures，导致全量门禁必有一套失败。

修复：聚合器直接调用现存测试模块；给该模块增加直接运行保护，被 import 时不触发自测。改动仅涉及 `src/selftest.mjs:62` 与 `tools/token-audit/selftest.mjs:133`，没有重建缺失审计 CLI，没有删套件或跳过失败。

验证：17 套 selftest 全绿；单独导入模块只打印探针自身的 `import-only`、不运行测试；38 个 `.mjs` 语法检查通过；最终文档门禁与 diff 检查见交付状态。npm 缓存改为进程环境中的临时路径，没有修改产品代码或用户 npm 配置。

尚未实测的部分：私公仓同步完整执行、远端发布/registry、远端 CI、实际长期会话 token 账单。相应建议基于代码边界，不写成运行成功。所有架构调整留待下一轮实施。
