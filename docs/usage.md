# 使用说明：工具与格式规范

本文是 worklog-kit 的命令契约与任务文件格式规范，对应用户本轮已确认的任务记录规范升级（任务内设计版本 r3）。角色分工、读取顺序与写作要求以 Skill 为准（[skills/worklog/SKILL.md](../skills/worklog/SKILL.md)），此处不重复其正文。

本轮规范升级已由用户确认，并已在本仓库源码、Skill 与任务记录中实现，尚未发布。已发布的 0.2.1 仍使用旧八项单元与旧验收读集，不支持 `accept --unit`；本轮能力可从源码运行，也可按 Skill 手工读取。工具状态见文末[实现状态](#实现状态)。

## 交付形态

| 能力 | 单 Skill 版 | 完全体 |
|---|---|---|
| 任务流程、角色划分、文档维护规则 | 同一份 Skill | 同一份 Skill |
| 任务文件与模板 | Skill 自带 | 同一套模板 |
| 任务定位与材料提取 | 目录查询加读文件 | `context` 按角色抽取 |
| 文档检查 | Agent 在相关范围检查 | `check` 检查结构与被引用位置 |

两版读写同一套任务文件：装上工具不转换格式，卸掉工具仍能继续工作，完全体不引入第二份状态库。

## 记录位置与命名

- 文档导航用 `docs/README.md`，工作选择用 `docs/todo.md`，主题正文优先复用已有文档或按需放入 `docs/topics/`。主题治理见 [治理规则](../skills/worklog/references/governance.md)，本项目全局说明指定为 [项目推进](topics/项目推进.md)。
- 任务目录：`docs/tasks/<YYYY-MM-DD-可读名称>/`，含 `state.md` 与 `details.md`。
- `references/` 只在确有长材料时创建，用于承接原始过程、旧结果与失败证据。一次会话即可完成、无需接续的小任务不建任务。
- T1、T2 等单元编号只在该任务内有效。

## 格式规范

以下标记用于定位与检查：写作者按此对齐，检查工具据此定位。语义是否足够完整仍由作者与设计者负责，格式齐全不代表已获授权。除标注为检查项的内容外，不要求每个任务都填满模板。

`state.md` 的稳定二级标题与字段：

| 二级标题 | 内容 |
|---|---|
| `## 当前` | 检查项：`目标：`、`阶段：探索\|设计\|施工\|待验收\|完成\|已取消`、`执行边界：<自然语言>`、`当前：`。建议再写 `方案版本：` 与 `阻塞：`，属说明字段，缺失不判错 |
| `## 进度` | 单元状态表，状态取 `未开始\|进行中\|待处理\|已自检`；本任务执行进度只在这里维护，只写状态与结果指针 |
| `## 下一步与阅读` | 下一步动作，以及带锚点的必读行与指针；只放当前步骤的最小共享必读，单元专属必读放对应 T 单元 |

`details.md` 用稳定二级标题：`目标与验收`、`探索结果`、`共同约束`、`当前设计`、各施工单元、`发现与经验`。按此顺序更好读；顺序不是判错条件，章节按需包含。不在 details 里再设全局「执行结果」章节：结果按单元维护在各自的「当前结果」。

- `## 当前设计` 建议首行标 `方案版本：r1`；待决定事项显式写「待定」。
- 探索与设计阶段允许章节标「待定」或尚无施工单元，此时只检查已声明的材料能否定位，不要求填满模板。
- 施工单元写作 `## T1 <标题>`，其下四个三级标题——`目标与验收`、`方案与范围`、`依赖与必读`、`当前结果`。`context` 的施工和验收（包括整体验收），以及 `check` 在施工、待验收、完成阶段，都要求所检查单元的四组材料完整、唯一且非占位。
- 无内容写「无」，不留占位符。
- 必读用独立一行写 `必读：[名称](相对当前文件的路径.md#锚点)`，一行一个，只标 Markdown 片段。同文件 `#锚点` 与带文件路径的锚点都支持。源码与测试给路径指针并注明相对哪个根，不把实现全文抄进任务文件。
- 登记进 `state.md` 进度表的施工单元要有对应章节；没有对应章节的建议写进「发现与经验」，不登记为单元。

两份文件的骨架见 [skills/worklog/templates/](../skills/worklog/templates/)，格式之外的角色约定见 [skills/worklog/references/](../skills/worklog/references/)。

## 记录纪律

以下是写作指导，内容取舍由作者负责。CLI 完整输出所选原文，不自动裁剪或合并；体积摘要与非阻断提示帮助定位过长材料，不判定内容是否充分。

- **短状态。** state 的「当前」只定位单元与动作，「执行边界」保留有效授权与限制，「阻塞」指向未解决问题；进度表只写状态与结果链接，「下一步」只写接下来要做什么和必要阅读。实现细节与验证证据在 details 保留一份，变更哪个字段就更新哪个字段。
- **集中落盘。** 完整批次结束时先更新 details 对应单元的当前结果，再更新发生变化的 state 字段；交接、中断与实质阻塞及时保存最小状态。短暂等待与轮询留在对话里，没有新事实就不重写文件。
- **当前结果与证据。** 单元「当前结果」按验收条件维护：写当前已实现、适用版本的验证证据、未验证项与遗留问题，更新当前结论，不逐提交追加施工日记。多轮实测保留版本、样本、配置、结果与可比条件；失败证据和旧版本结果继续可查，长历史或原始输出用普通链接承接，当前摘要指出尚未解决的失败。
- **共享设计。** 「当前设计」只写总体数据流、共享接口、不变量与跨单元决策；专属实现与依赖放对应 T 单元。公共章节会随每个施工单元加载，把详细设计留在公共章节再添加单元指针不能减少读取。
- **按需恢复。** 同上下文同单元复用有效材料，切换单元只补新单元和新增依赖；压缩或换会话从 state 定位，再读当前所需章节。角色变化时补齐该角色尚未加载的材料。验收从结果摘要沿证据指针核实。阻塞由外部条件引起且条件未变时，不再新开诊断轮。CLI 可用时优先按角色提取，手工读取遵循相同范围。
- **必读归属。** state.md 的「下一步与阅读」只留当前接续所需的共享必读，过时条目清理；历史结论与其它材料用普通链接；单元专属必读放对应 T 单元。语法与一层展开规则见[格式规范](#格式规范)。

## 命令

三个入口都只做薄封装：建任务、更新状态、记录结果仍由 Agent 编辑普通文件完成。零运行依赖，Node >= 20。全局只有 `-h`/`--help` 与 `-v`/`--version`，写在任何位置（含子命令之后）都只打印帮助或版本，不执行命令。

| 命令 | 用法 | 行为 |
|---|---|---|
| `init` | `worklog-kit init [Skill 目标目录]` | 把包内 `skills/worklog` 整目录导出，默认目标 `.agents/skills/worklog`（相对当前目录）。内容相同的文件跳过；存在冲突时先预检后整体停止，不覆盖也不部分复制。不创建项目 todo，不写项目 AGENTS、CI 或任务文件；todo/topic 模板随 Skill 整目录导出 |
| `context` | `worklog-kit context [任务目录或任务名] [--role explore\|design\|implement\|accept] [--unit T1]` | 只读打印接续材料。无参数时输出 todo 原文，缺失时回退任务列表；指定任务且不带 `--role` 时只输出 state 的三个固定章节。`implement` 必须带 `--unit` |
| `context --list` | `worklog-kit context --list` | 显式调用任务列表，不依赖 todo；列出全部未完成任务及缺少 state 的提示，完成或已取消的任务须显式给任务名 |
| `check` | `worklog-kit check [路径]` | 只读检查本地 Markdown 链接与片段、任务核心格式与状态指向的单元，默认范围 `docs` 并跳过 `docs/history` |

无参数 `context` 的契约：

| todo 情况 | 输出与退出码 |
|---|---|
| 存在且可读 | 来源标识、未经截断的原文、末尾提示 `context --list`；0 |
| 缺失 | 回退原任务列表并建议按需创建索引；0 |
| 空或全空白 | 明确报空；1 |
| 非文件或访问、读取失败 | 明确报路径或读取问题；2 |

索引中的链接（包括看似必读的行）不展开，也不附加 README、主题或任务列表。`--list` 与任务位置参数、`--role`、`--unit` 互斥；无任务却携带角色或单元也报错，退出码 2。帮助与版本仍优先。主题文件不是 context 目标，用文件能力按章节读取。

任务名按 `docs/tasks` 下的目录名解析（目录内须有 `state.md`），也可以直接给仓根内的任务目录路径。

`context` 的材料组成。任何角色都先给 `state.md` 的「当前」「进度」「下一步与阅读」：

| 角色 | 追加的 details.md 章节 |
|---|---|
| 无（只给状态） | 不展开 details，也不展开必读 |
| `explore` | 必需「目标与验收」；存在时附「探索结果」「共同约束」 |
| `design` | 「目标与验收」「探索结果」「共同约束」「当前设计」 |
| `implement` | 「共同约束」「当前设计」与 `--unit` 指定的单元 |
| `accept` | 「目标与验收」「共同约束」「当前设计」；指定 `--unit` 时加该单元全文，未指定时加全部单元的目标与验收、依赖与必读、当前结果 |

无角色不输出 state 的额外章节，也不展开必读。验收默认读集仅为入口：无论是否指定单元都带共享的「目标与验收」「共同约束」「当前设计」；指定单元时再对齐该单元四组材料，整体验收时再汇集全部单元的目标与验收、依赖与必读、当前结果，并按任务给出的方案定位打开相关方案；验收者还须沿「当前结果」的指针补读相关单元设计、适用共同约束与约束片段，不加载无关单元。全局问题还需读指定全局说明与相关主题，并用 `context --list` 枚举未完成任务、按需读 state；无 CLI 时浏览任务目录。不能仅凭 todo 判断全局完成。

指定任务成功提取时附一行正文体积摘要，列出所选章节与一层必读的 UTF-8 字节数，不含来源标签等输出包装，也不代表模型 token 数。正文仍完整输出；无参索引和 `--list` 保持原输出。

施工和验收要求单元的四个三级标题齐备且不重复，四组材料都不能停在待定或占位，「当前设计」也不能是待定。整体验收至少要有一个单元；「尚未开始；未验证」是当前事实，可以作为结果，空白或「待定」不能代替结果。这项判断由 `context` 与 `check` 共用。必需章节、指定单元或必读引用缺失、重复、无法解析时，命令报出问题并以退出码 1 结束，不输出看似完整的材料。需读取单元时，旧八项标题或全局「执行结果」残留会明确提示迁移；历史报告仍可作为普通 Markdown 阅读。

必读标记的展开规则：`必读：` 行只接受一条本地 Markdown 链接（`相对路径.md` 或 `相对路径.md#锚点`），源码等材料用普通指针行；片段按 ATX 标题锚点定位，锚点生成与 `check` 同一套规则（同名标题依次追加 `-1`、`-2`），必须存在且定位唯一。只展开一层，不递归；已在所选章节里完整出现的片段不重复注入；围栏内的示例必读不算。同文件 `#锚点` 与带文件路径的锚点都按此规则解析。

有角色时从 state 与所有所选 details 章节收集必读。公共章节只放共享必读，对每个 `--unit` 都生效；单元专属设计与必读放对应 T 单元。工具不按单元过滤公共必读，也不识别语义依赖，片段依赖须在任务里显式声明。

## 检查范围与语法支持

`check` 判定可明确判定的结构问题，不判定语义正确，也不联网。普通本地链接与锚点检查自然覆盖 todo 和主题；不强制创建 todo、主题目录或固定章节，不检查全量登记、事实新鲜度、优先级或授权，也不检查[记录纪律](#记录纪律)里的落盘时机、结果写法与必读归属。

- 本地链接：行内链接与同文件引用式链接（`[标签]: 目标` 必须先有定义），相对路径按所在文件解析，且不得越出仓根；带 scheme 的外部地址跳过。带 `#锚点` 时校验目标 Markdown 的标题锚点存在。
- 任务结构：`state.md` 与 `details.md` 是否齐备；「当前」节的阶段是否属六个枚举，`目标：`、`阶段：`、`执行边界：`、`当前：` 四个检查项字段缺失时报错；`state.md` 是否含「当前」「进度」「下一步与阅读」；`details.md` 按阶段要求章节——探索只要「目标与验收」，设计加「探索结果」「共同约束」「当前设计」，施工、待验收、完成要求「目标与验收」「共同约束」「当前设计」并要求单元可用，已取消只要「目标与验收」。
- 单元与状态指向：`state.md` 进度表里的 `T<n>` 必须能在 `details.md` 唯一定位；施工、待验收、完成阶段的所有单元要有四个三级标题，四组材料均不能是待定或占位，「当前设计」不能是待定，进度表至少要列一个单元。
- 范围：给目录就递归其下的 `.md`（跳过 `node_modules`、`.git`、`dist`、`build`），给单文件只查该文件；默认跳过 `docs/history`，显式给出该目录或其子路径时才按历史材料检查。任务结构检查不挑范围入口：只要范围内出现 `docs/tasks` 布局或任务目录（含 `state.md` 或 `details.md`），就按上述规则检查，换入口不改变结论。
- 退出码：`0` 通过，`1` 发现问题，`2` 范围不存在或越出仓根等输入问题。

任务体积另给整理提示：state 整体超过 4096B、「当前」节单个字段值（含续行）超过 1024B、details 的共同约束或当前设计超过 8192B、单元正文超过 16384B、单元「当前结果」超过 1024B 时提示。按 UTF-8 字节计，不按行数或 token 计；阈值用于定位可能过长的材料，不是合法性上限。提示与结构错误分开，单有体积提示仍退出 0，有结构或引用错误仍退出 1。工具保留正文，作者按实际依赖和证据决定是否整理。

Markdown 识别是够用即止的最小实现，不是通用解析器。支持：三个及以上反引号或波浪线的围栏（围栏内容跳过，字段行读取同样遮蔽围栏）、行内代码遮蔽（代码里的示例链接不算链接）、行首第 0 列的 ATX 标题 `#{1,6}`（末尾 `#` 忽略）、行内链接 `[文字](目标)`（含整体 `<目标>` 与成对括号路径）、图片、同文件引用式链接与定义行。整体用尖括号包裹的目标按真实链接检查；只有尖括号散布在目标里的（模板骨架占位）跳过。标题锚点由标题文本生成：转小写，保留中文、字母、数字、`-`、`_`，其余字符去掉，空白转 `-`，同名标题依次追加 `-1`、`-2`。

这些形态之外的写法按普通文本处理，不会被校验：setext 标题（`===` 或 `---` 下划线式）、缩进的 ATX 标题、HTML 块、脚注、外部网址可达性。检查通过只说明已覆盖的形态里没发现问题。工具也不判断授权：格式完整、检查通过都不表示已经获准执行。

## 实现状态

三个入口已实现（入口 `bin/worklog.mjs`，包内只分发 `bin`、`src`、`skills`），CLI 仅使用 Node 内置模块。本轮源码已支持四组单元、施工与验收的单元读集、整体验收汇集、同文件锚点与单元体积提示；验证与验收记录见[优化任务](tasks/2026-09-22-精简记录与接续/state.md)。npm 已发布版本仍为 0.2.1，采用旧八项单元和旧验收读集，不支持 `accept --unit`。从源码运行：

```bash
node /绝对路径/worklog-kit/bin/worklog.mjs --help
node /绝对路径/worklog-kit/bin/worklog.mjs init                    # 导出 Skill 到 .agents/skills/worklog
node /绝对路径/worklog-kit/bin/worklog.mjs context title-search --role implement --unit T2
node /绝对路径/worklog-kit/bin/worklog.mjs check
```

初始化只导出 Skill 文件：不装依赖，不写项目规则、CI 或任务文件。可运行的接续样例见 `examples/title-search/`。

先前工具版本的自检见 [原任务记录](tasks/2026-09-19-task-hub/state.md)。旧记录的统一迁移方式见 [迁移说明](migration.md)。
