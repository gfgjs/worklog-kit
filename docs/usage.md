# 使用说明：工具与格式规范

本文是 worklog-kit 的命令契约与任务文件格式规范。角色分工、读取顺序与写作要求以 Skill 为准（[skills/worklog/SKILL.md](../skills/worklog/SKILL.md)），此处不重复其正文。

## 交付形态

| 能力 | 单 Skill 版 | 完全体 |
|---|---|---|
| 任务流程、角色划分、文档维护规则 | 同一份 Skill | 同一份 Skill |
| 任务文件与模板 | Skill 自带 | 同一套模板 |
| 任务定位与材料提取 | 目录查询加读文件 | `context` 按角色抽取 |
| 文档检查 | Agent 在相关范围检查 | `check` 检查结构与被引用位置 |

两版读写同一套任务文件：装上工具不转换格式，卸掉工具仍能继续工作，完全体不引入第二份状态库。

## 记录位置与命名

- 文档导航用 `docs/README.md`，工作选择用 `docs/todo.md`，主题正文优先复用已有文档或按需放入 `docs/topics/`。主题治理见 [治理规则](../skills/worklog/references/governance.md)，本项目全局说明指定为 [项目推进](topics/项目推进.md)。
- 任务目录：`docs/tasks/<YYYY-MM-DD-可读名称>/`，含 `state.md` 与 `details.md`。
- `references/` 只在确有长材料时创建。一次会话即可完成、无需接续的小任务不建任务。
- T1、T2 等单元编号只在该任务内有效。

## 格式规范

以下标记用于定位与检查：写作者按此对齐，检查工具据此定位。语义是否足够完整仍由作者与设计者负责，格式齐全不代表已获授权。除标注为检查项的内容外，不要求每个任务都填满模板。

`state.md` 的稳定二级标题与字段：

| 二级标题 | 内容 |
|---|---|
| `## 当前` | 检查项：`目标：`、`阶段：探索\|设计\|施工\|待验收\|完成\|已取消`、`执行边界：<自然语言>`、`当前：`。建议再写 `方案版本：` 与 `阻塞：`，属说明字段，缺失不判错 |
| `## 进度` | 单元状态表，状态取 `未开始\|进行中\|待处理\|已自检`；本任务执行进度只在这里维护 |
| `## 下一步与阅读` | 下一步动作，以及带锚点的必读行与指针 |

`details.md` 用稳定二级标题：`目标与验收`、`探索结果`、`共同约束`、`当前设计`、各施工单元、`执行结果`、`发现与经验`。按此顺序更好读；顺序不是判错条件，章节按需包含。

- `## 当前设计` 建议首行标 `方案版本：r1`；待决定事项显式写「待定」。
- 探索与设计阶段允许章节标「待定」或尚无施工单元，此时只检查已声明的材料能否定位，不要求填满模板。
- 施工单元写作 `## T1 <标题>`，其下八个三级标题——`目标与验收`、`依赖与前提`、`必读材料`、`修改范围`、`实现路径`、`最低验证`、`回交条件`、`回传要求`——在把该单元当可执行材料交付（`context --role implement`）时才要求齐备。
- 无内容写「无」，不留占位符。
- 必读用独立一行写 `必读：[名称](相对当前文件的路径.md#锚点)`，一行一个，只标 Markdown 片段。源码与测试给路径指针并注明相对哪个根，不把实现全文抄进任务文件。
- 登记进 `state.md` 进度表的施工单元要有对应章节；没有对应章节的建议写进「发现与经验」，不登记为单元。

两份文件的骨架见 [skills/worklog/templates/](../skills/worklog/templates/)，格式之外的角色约定见 [skills/worklog/references/](../skills/worklog/references/)。

## 命令

三个入口都只做薄封装：建任务、更新状态、记录结果仍由 Agent 编辑普通文件完成。零运行依赖，Node >= 20。全局只有 `-h`/`--help` 与 `-v`/`--version`，写在任何位置（含子命令之后）都只打印帮助或版本，不执行命令。

| 命令 | 用法 | 行为 |
|---|---|---|
| `init` | `worklog-kit init [Skill 目标目录]` | 把包内 `skills/worklog` 整目录导出，默认目标 `.agents/skills/worklog`（相对当前目录）。内容相同的文件跳过；存在冲突时先预检后整体停止，不覆盖也不部分复制。不创建项目 todo，不写项目 AGENTS、CI 或任务文件；todo/topic 模板随 Skill 整目录导出 |
| `context` | `worklog-kit context [任务目录或任务名] [--role explore\|design\|implement\|accept] [--unit T1]` | 只读打印接续材料。无参数时输出 todo 原文，缺失时回退任务列表；指定任务且不带 `--role` 时只输出 state 的三个固定章节。`implement` 必须带 `--unit` |
| `context --list` | `worklog-kit context --list` | 显式调用任务列表，不依赖 todo；列出全部未完成任务及缺少 state 的提示，完成或已取消的任务须显式给任务名 |
| `check` | `worklog-kit check [路径]` | 只读检查本地 Markdown 链接与片段、任务核心格式与状态指向的单元，默认范围 `docs` 并跳过 `docs/history` |

无参数 `context` 的契约：

| todo 情况 | 输出与退出码 |
|---|---|
| 存在且可读 | 来源标识、未经截断的原文、末尾提示 `context --list`；0 |
| 缺失 | 回退原任务列表并建议按需创建索引；0 |
| 空或全空白 | 明确报空；1 |
| 非文件或访问、读取失败 | 明确报路径或读取问题；2 |

索引中的链接（包括看似必读的行）不展开，也不附加 README、主题或任务列表。`--list` 与任务位置参数、`--role`、`--unit` 互斥；无任务却携带角色或单元也报错，退出码 2。帮助与版本仍优先。主题文件不是 context 目标，用文件能力按章节读取。

任务名按 `docs/tasks` 下的目录名解析（目录内须有 `state.md`），也可以直接给仓根内的任务目录路径。

`context` 的材料组成。任何角色都先给 `state.md` 的「当前」「进度」「下一步与阅读」：

| 角色 | 追加的 details.md 章节 |
|---|---|
| 无（只给状态） | 不展开 details，也不展开必读 |
| `explore` | 必需「目标与验收」；存在时附「探索结果」「共同约束」 |
| `design` | 「目标与验收」「探索结果」「共同约束」「当前设计」 |
| `implement` | 「共同约束」「当前设计」与 `--unit` 指定的单元 |
| `accept` | 「目标与验收」「当前设计」「执行结果」 |

无角色不输出 state 的额外章节，也不展开必读。验收默认读集仅为入口；验收者沿执行结果指针补读相关 T 单元设计、适用共同约束与约束片段，不加载无关单元。全局问题还需读指定全局说明与相关主题，并用 `context --list` 枚举未完成任务、按需读 state；无 CLI 时浏览任务目录。不能仅凭 todo 判断全局完成。

`implement` 的要求更严：该单元的八个三级标题要齐备且不重复，八个字段都不能停在待定或占位，「当前设计」也不能是待定。必需章节、指定单元或必读引用缺失、重复、无法解析时，命令报出问题并以退出码 1 结束，不输出看似完整的材料。

必读标记的展开规则：`必读：` 行只接受一条本地 Markdown 链接（`相对路径.md` 或 `相对路径.md#锚点`），源码等材料用普通指针行；片段按 ATX 标题锚点定位，锚点生成与 `check` 同一套规则（同名标题依次追加 `-1`、`-2`），必须存在且定位唯一。只展开一层，不递归；已在所选章节里完整出现的片段不重复注入；围栏内的示例必读不算。

有角色时从 state 与所有所选 details 章节收集必读。公共章节只放共享必读，对每个 `--unit` 都生效；单元专属设计与必读放对应 T 单元。工具不按单元过滤公共必读，也不识别语义依赖，片段依赖须在任务里显式声明。

## 检查范围与语法支持

`check` 判定可明确判定的结构问题，不判定语义正确，也不联网。普通本地链接与锚点检查自然覆盖 todo 和主题；不强制创建 todo、主题目录或固定章节，不检查全量登记、事实新鲜度、优先级或授权。

- 本地链接：行内链接与同文件引用式链接（`[标签]: 目标` 必须先有定义），相对路径按所在文件解析，且不得越出仓根；带 scheme 的外部地址跳过。带 `#锚点` 时校验目标 Markdown 的标题锚点存在。
- 任务结构：`state.md` 与 `details.md` 是否齐备；「当前」节的阶段是否属六个枚举，`目标：`、`阶段：`、`执行边界：`、`当前：` 四个检查项字段缺失时报错；`state.md` 是否含「当前」「进度」「下一步与阅读」；`details.md` 按阶段要求章节——探索只要「目标与验收」，设计加「探索结果」「共同约束」「当前设计」，施工、待验收、完成要求「目标与验收」「当前设计」「执行结果」，已取消只要「目标与验收」。
- 单元与状态指向：`state.md` 进度表里的 `T<n>` 必须能在 `details.md` 唯一定位；施工、待验收、完成阶段的单元要有八个三级标题，「目标与验收」「实现路径」「最低验证」不能是待定或占位，「当前设计」不能是待定，进度表至少要列一个单元。
- 范围：给目录就递归其下的 `.md`（跳过 `node_modules`、`.git`、`dist`、`build`），给单文件只查该文件；默认跳过 `docs/history`，显式给出该目录或其子路径时才按历史材料检查。任务结构检查不挑范围入口：只要范围内出现 `docs/tasks` 布局或任务目录（含 `state.md` 或 `details.md`），就按上述规则检查，换入口不改变结论。
- 退出码：`0` 通过，`1` 发现问题，`2` 范围不存在或越出仓根等输入问题。

Markdown 识别是够用即止的最小实现，不是通用解析器。支持：三个及以上反引号或波浪线的围栏（围栏内容跳过，字段行读取同样遮蔽围栏）、行内代码遮蔽（代码里的示例链接不算链接）、行首第 0 列的 ATX 标题 `#{1,6}`（末尾 `#` 忽略）、行内链接 `[文字](目标)`（含整体 `<目标>` 与成对括号路径）、图片、同文件引用式链接与定义行。整体用尖括号包裹的目标按真实链接检查；只有尖括号散布在目标里的（模板骨架占位）跳过。标题锚点由标题文本生成：转小写，保留中文、字母、数字、`-`、`_`，其余字符去掉，空白转 `-`，同名标题依次追加 `-1`、`-2`。

这些形态之外的写法按普通文本处理，不会被校验：setext 标题（`===` 或 `---` 下划线式）、缩进的 ATX 标题、HTML 块、脚注、外部网址可达性。检查通过只说明已覆盖的形态里没发现问题。工具也不判断授权：格式完整、检查通过都不表示已经获准执行。

## 实现状态

三个入口已实现（入口 `bin/worklog.mjs`，包内只分发 `bin`、`src`、`skills`），零运行依赖。已发布 npm，可全局安装后使用 `worklog-kit` 命令；从源码运行：

```bash
node /绝对路径/worklog-kit/bin/worklog.mjs --help
node /绝对路径/worklog-kit/bin/worklog.mjs init                    # 导出 Skill 到 .agents/skills/worklog
node /绝对路径/worklog-kit/bin/worklog.mjs context title-search --role implement --unit T2
node /绝对路径/worklog-kit/bin/worklog.mjs check
```

初始化只导出 Skill 文件：不装依赖，不写项目规则、CI 或任务文件。可运行的接续样例见 `examples/title-search/`。
