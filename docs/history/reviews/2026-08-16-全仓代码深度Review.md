## 1. 总体判断

工程质量在同类 CLI 工具里属第一梯队:**零运行期依赖**下的自研 JSONC 状态机、CommonMark 子集解析(围栏/转义竖线/尖括号目标/括号配对)、JSON Schema draft-07 子集校验器、逐级迁移 + 外科编辑保注释 + 备份回滚 + 写后复验、closeout/team 事务化 + 故障注入回归,以及「单一实现防分叉」(FM_DELIM_RE / makeFenceSkipper / splitRow / collectGraphDocs / isCurrentAuthority / todayLocal)的纪律贯穿全仓。测试不是装饰:selftest 对坏路径、敌意输入、CRLF/BOM/NFC、Windows 盘符、symlink 逃逸均有精确断言,且大量用例注明了真实踩坑来源。

主要短板集中在三处:**①公开快照的聚合 selftest 当前就是红的(登记路径漂移)**;**②门与迁移器之间的"同语义两把尺"仍有残留**(本轮新抓到 closeout 台账改写一处,上轮 R2 系列多处未闭环);**③readdir+statSync 家族对悬空 symlink 无守卫**,与 walk() 的防护口径不一致。

## 2. 本轮新发现(按严重级)

### N-01 · P1 · 聚合 selftest 在本仓确定性红:token-audit 登记路径漂移 + 入口文件无直跑能力

- 证据:`src/selftest.mjs:62` 登记 `externalToolSelftest('tools/token-audit.mjs', ['--selftest'])`;但 `tools/token-audit.mjs` **不存在**——token-audit 已重构为目录(`tools/token-audit/`:model/estimator/parse-claude/parse-codex/report/selftest 六件),实际入口是 `tools/token-audit/selftest.mjs`。守卫如实报红:`✗ 源码仓外部工具套件入口缺失:...\tools\token-audit.mjs`。
- 连带:`tools/token-audit/selftest.mjs` 只 `export function selftest()`,**没有直跑入口**(`import.meta.url === argv[1]` 判定缺失)——直接 `node tools/token-audit/selftest.mjs` 零断言静默 exit 0(假绿)。它 presumably 由私源一个未导出的 wrapper `tools/token-audit.mjs` 调起,公开快照看不到该 wrapper。
- 影响链:`.github/workflows/ci.yml:33` 跑 `node bin/worklog.mjs selftest` ⇒ 公开仓 main 的 CI 此刻应红(若 Actions 已启用);发布链 `release-selftest --full` 走"dev-only suite skipped"分支不受累,恰因 files 清单不分发 tools——**私源自测掩盖了公开面断裂**,正是 e2e 头注释里"package == repo 的遮蔽"又一实例,这次遮蔽方向相反(公开面独有红)。
- 修法(三选一,建议 a):a) 私源补回/导出 `tools/token-audit.mjs` wrapper(或确认其被误 exclude 后修复导出);b) SUITES 改登记 `tools/token-audit/selftest.mjs` 并给该文件加直跑入口;c) 二者都做(登记目录入口 + import.meta 直跑),wapper 淘汰。**无论哪种,`tools/token-audit/selftest.mjs` 都应补直跑入口**——"能被聚合器调起"与"能被单独复跑"都是 selftest 的契约(各门自己的 `--selftest` 同款)。

### N-02 · P2 · upgrade 的 closeout 台账改写未复用 `splitRow`/`makeFenceSkipper`:裸 `split('|')` + fence-blind

- 证据:`src/upgrade.mjs:619-626`(reconcileGenerated ②):`const cells = l.split('|'); ... cells[2]?.trim() !== 'todo' || cells[3]?.trim() !== \`repo:${oldTodoTarget}\``。
- 同仓已确立的两条纪律在此失守:
  - **F-023**(转义竖线):`src/lib/frontmatter.mjs` 的 `splitRow` 就是为「格内 `\|` 是字面竖线」造的,门侧 checkCloseouts/collectDeclaredIds 全走它;此处裸 split 未复用该语义,对异常行可能发生列位错读。需要校正的是:当前 closeout ID 合约只接受 `^[FD]-\d{3}$`,`F-0\|3` 并不是合法 ID;若保留该行,门会先报 `closeout.rowIdInvalid`,此前所写“迁移后必红 `closeout.lineStatusMismatch`、工具自造门红”的具体因果链不成立。合法 `naReason` 含 `a\|b` 的 `F-002` 在探针中可正常改写且保留转义内容。
  - **B8**(围栏感知):逐行改写不经过 `makeFenceSkipper`——closeout 正文围栏示例里的 `| D-001 | todo | repo:docs/todo.md |` 示例行也会被机械改写(改示例不改语义,但与全仓"围栏内是示例不是数据"的既定读法分叉;示例被改后与门侧 parseTables 的视野也不一致)。
- 探针复现(临时仓,generated 档 flip 全流程):含 `F-001`(正常)/`F-0\|3`(非法 ID 格)/`F-002`(naReason 含 `a\|b`)/围栏示例 `F-009` 四行的 closeout 走真 `upgrade`——结果:改写命中 **3 行**(`F-001`、`F-002`、**围栏示例 `F-009`**);`F-0\|3` 行**漏改**。这同时证实 fence-blind,也说明先前“命中 2 行、F-002 该轴无损”的记录不准确。围栏示例虽不进入 `parseTables` 语义,仍被迁移器改写而造成文档漂移;这是本项保留的主要缺陷,严重度由 P1 下调为 P2。
- 修法:改写循环改用 `splitRow(l)` 取列、写回时按原行重新拼装(splitRow 已把 `\|` 反转义,写回需保转义——最稳妥是仅对命中行做**单元格级替换**而非重排整行),并在行循环外挂 `makeFenceSkipper()` 跳过围栏行。补 selftest:合法 todo 行、含 `\|` 的原因列、非法/异常 ID 不误导诊断、围栏内示例 todo 行各一例。

### N-03 · P2 · readdir+statSync 家族对悬空 symlink 无守卫,门禁可被单文件打崩

- 证据(模式均为 `statSync(p).isDirectory()` 未 try/catch,悬空 symlink 触发 ENOENT 裸栈):
  - `src/check-index.mjs:33`(docs 顶层)、`:72`(worklogs);
  - `src/check-docs.mjs:329`(checkCloseouts)、`:435`(checkTeamAndTaskNames)、`:483`(events 内);
  - `src/doctor.mjs:73`(fatTrio)、`:185-194`(stale trio);
  - `src/tasks.mjs:146`(mainList);
  - `src/init.mjs:359`(dirs 派生);
  - `src/build-index.mjs:62`(collectTasks);
  - `src/install-skills.mjs:30`(collectFiles)。
- 对照:`walk()`(`src/lib/fsutil.mjs:37`)对每项 statSync 已有 try/catch + 注释"悬空 symlink/竞态删除:跳该项,不拖垮整扫";`repoRootFiles` 同样有守卫。同一仓两种口径。
- 影响:门禁的失败形态应是"exit 1 + 违规清单",不是异常栈。一个悬空链接(如编辑器临时替换文件的中间态被扫描撞上,或恶意/误放的死链)即可让 check/index/doctor/list 全部裸崩。
- 探针复现:docs 顶层置一悬空 junction(建后删靶)再跑 `checkIndex` —— **裸崩 ENOENT**(需 docs/README.md 存在才走得到该行;缺 README 时在 `index.missing` 分支提前返回,掩盖该路径)。同一 fixture 下 `walk()` 家族的 1a 扫描按设计跳过该项不崩——同仓两口径实证。
- 修法:抽一个 `isDirSafe(p)`(或复用/扩驻 fsutil)统一替换上述 **15 个未保护调用点**;selftest 补一个"docs 顶层含悬空 symlink 时 check 报受控结果不崩"用例。

### N-05 · P3 · `applyChanges` 备份戳秒级精度,同秒重跑同文件会覆写上一份 `.bak`
