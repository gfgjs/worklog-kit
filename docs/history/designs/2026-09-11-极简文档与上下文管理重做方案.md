# 极简文档与上下文管理：从零重做方案

日期：2026-09-11。状态：方案已形成，尚未实施。

本轮交付仅为本文。按照本次请求中“本轮先出方案并落盘”的范围，本轮不删除旧文件、不改产品代码、不安装 Skill、不发布。请求中的重写和运行验收要求，落实为下文的实施范围和验收条件。

背景材料为 `docs/reviews/2026-09-09-产品流程与Skill精简方案.md`，只用于理解现状。本文重新决定产品模型，不继承其中关于三件套、兼容、迁移、归档、治理门禁或工具链的保留要求。

## 1. 设计结论

**新产品是一份独立 Skill，指导 Agent 直接维护普通项目文件；有跨会话信息时，按需增加一份 `CONTEXT.md`。首版不提供 CLI，不包含生产运行时代码。**

一句话工作流：

> 开始任务 → 读取已有上下文和本次需要的项目文件 → 工作 → 有必要时更新上下文 → 下次继续。

核心只剩两个概念：

1. **项目文档**：给人和后续开发者使用的当前说明、规范或交付物，按项目实际需求维护。
2. **项目上下文**：普通文档和源码不能低成本恢复、但后续工作仍需要知道的少量信息。

上下文默认放在项目根目录的一份 `CONTEXT.md` 中，只有两个内容区域：**长期有效**、**未完成任务**。这是阅读约定，不是机器校验的格式协议。

不为每个任务创建文件；不把“用了本工具”变成建档理由。没有需要留下的信息时，项目可以一个工具文件也不增加。

### 为什么连 CLI 一起删除

从目标倒推，首版没有必须由程序完成的操作：

| 可能保留的命令 | 实际需求 | 更直接的完成方式 |
|---|---|---|
| init / start | 首次留下有效信息 | Agent 创建一个普通文件；没有信息就不创建 |
| resume / list | 了解有效上下文与未完工作 | 读取 `CONTEXT.md`；没有目录扫描、索引或选中任务状态 |
| note / checkpoint | 更新信息、缩短上下文 | Agent 判断后直接改写相关内容；命令无法替代语义判断 |
| closeout | 结束任务并保留必要事实 | 更新对应项目文档或长期信息，删除完成任务的小节 |
| check / doctor | 确认文件有助于接续 | 检查实际内容并做接续演练；格式正确不能证明记忆真实、有效 |
| skills / install | 使用 Skill | 复制一个 Skill 目录，或直接把其中说明交给 Agent |

给这些动作再包一层命令，会增加安装、参数、异常处理和发布成本，没有带来不可替代的能力。因此不保留“可选 CLI 壳”，也不预留以后接回 CLI 的接口。

**完整工具交付 = 使用说明 + 独立 Skill + 许可；Skill 单独使用 = 只取 Skill 目录。** “完整工具链”不意味着必须存在第二个执行组件。

这项选择主动放弃自动建档、自动归档、格式门禁和集中任务管理。三个核心目标通过直接文件读写和 Skill 的取舍规则完成，不承诺程序化的记忆质量保证。

## 2. 从零回答：究竟要留下什么

一条信息值得进入上下文，需要同时满足：后续工作会用到；目前仍然有效；从现有项目文件和实际状态中不能低成本得到。尚未确认的事项可以作为未完成任务中的疑问保留，不能写成既定结论。

| 信息 | 新落点 | 保留方式 |
|---|---|---|
| 项目用途、使用方式、稳定开发入口 | 通常是 README | 优先维护原文；上下文不复制一份介绍 |
| 没有其他合适落点、后续仍需要的项目背景 | CONTEXT 的长期有效区域 | 用短句说明当前事实；形成正式说明后移去对应文档 |
| 已确认的关键决策、长期约束 | 已有规范或长期有效区域，二选一 | 结论和关键原因放在同一处，不另造 ADR 台账 |
| 当前产品边界、尚有效的方向性约定 | 正式说明或长期有效区域 | 只记不能从当前代码推导的意图，不存功能清单镜像 |
| 用户认可、仍待继续的工作 | 未完成任务区域 | 保存目标、当前落点、必要决定或疑问、下一步 |
| 未完成任务的验证事实 | 对应任务的小节 | 只记影响接续的结果、验证范围与未验证部分 |
| 当次已完成的小改动、最终答复已交付的结果 | 通常不进入上下文 | 有独立文档价值才更新项目文档 |
| 文件列表、依赖版本、分支、提交号、diff、测试当前是否通过 | 需要时读取实际来源 | 不维护第二份仓库快照；必要复现定位信息可随未完问题保留 |
| 命令输出、逐次工具调用、思考过程、尝试流水账 | 不保存 | 未解决失败只保留当前现象、关键证据及会影响下一步的已排除原因 |
| 已失效决策、完成任务、重复说明、推测性未来功能 | 删除或不写入 | 不转存到另一套档案系统 |

信息的去留依据是对未来工作的价值，而不是“发生过”“曾经写入过”或“可能以后有用”。

### 真正有长期价值的文档

默认只需要项目自己的 README。API 契约、部署说明、设计稿、研究结果等，只有在其内容需要独立阅读、执行或交付时才单独成文；不预建 `designs/reviews/decisions/runbooks/experience` 等分类目录。

文档较大时，在上下文中给出**为什么下一步需要读它，以及准确路径或章节**。不复制全文，也不把每个文档都登记到索引表。与本任务无关的文档不必预读。

已有文档是某项事实的正确落点时，直接修改它。上下文仅保留任务接续所需的引用；没有当前引用需求时，连这个引用也可以不留。

## 3. 唯一新增文件：CONTEXT.md

### 文件规则

- 默认位置为项目根目录 `CONTEXT.md`，UTF-8、普通 Markdown，无 frontmatter、ID、状态枚举或 schema。
- 第一次出现值得跨会话保留的信息时才创建；不生成空模板和占位目录。
- 用户明确指定已有上下文文件时，使用那一份，不另造 `CONTEXT.md`，也不建立路径配置或注册表。
- 既有项目指令照常由宿主 Agent 读取。本工具不自动创建、覆盖或注入 `AGENTS.md`、`CLAUDE.md` 等指令文件。
- 新会话使用 Skill 后先读这份上下文；若宿主不会自动触发 Skill，用户在任务中明确要求使用它。不把自动触发或后台载入当作产品保证。
- 更新相关小节，不机械追加“第 N 轮”“今日进度”。内容为空的小节可以删除，整个文件没有有效内容时可以删除整个文件。

### 同一个文件里，按信息寿命更新

**长期有效**保存项目级的当前事实、约束及理由；事实改变时替换旧说法。任务中形成的已确认长期决策可以当场更新这里，不等待收口，不先登记候选再提升。

**未完成任务**保存仍需继续的工作。一个任务通常只需说清：

1. 要达成什么，怎样才算完成。
2. 当前实际落点，以及继续工作依赖的关键决定和理由。
3. 哪些工作或验证尚未完成，是否有阻塞或待确认问题。
4. 下一步可以执行的具体动作，必要时指向相关文件。

这些是内容要求，不是四个强制字段；两句话足够时就写两句话。不要求填写“无”、日期、负责人、百分比或完整已完成步骤。

### 假想示例：一个未完成任务需要留下的内容

以下内容用于展示格式，不代表本仓已经实施或验证：

```markdown
# 项目上下文

## 长期有效

- 项目只处理本地笔记。用户已确认文件不得上传到服务端；搜索也在本地完成。

## 未完成任务

### 增加标题搜索

目标：支持按标题筛选笔记，保留原有排序。
当前：过滤逻辑和空结果提示已实现；相关单元测试通过，键盘操作尚未验证。
决定：先采用子串匹配，因为本轮只要求标题查找；暂不做全文索引。
未完：输入法组合输入时仍可能提前筛选，需要检查输入事件处理。
下一步：在 src/search.js 修复组合输入，再验证中文输入和上下键选择。
```

任务完成后删除“增加标题搜索”小节。若没有新的长期事实，结束时无需追加完成摘要；交付结果在用户答复中说明，产品使用行为需要说明时更新 README。

### 为什么首版不拆成 MEMORY.md 和 TASK.md

两者寿命不同，但同一 Agent 能直接修改一个文件中的不同段落，不需要两个文件才能实现替换和淘汰。拆分会增加默认读取数、缺文件判断和双文件更新步骤。

首版采用一个文件。单任务默认一小节，真实存在的多个未完成任务才增加同级小节；文件标题本身足够识别任务，不发号、不保存“当前选中任务”。

## 4. 任务完整流程和容易遗漏的情况

### 开始与恢复

1. 使用 Skill，读取已有上下文；不存在时直接开始工作。
2. 结合用户本轮目标，只读取相关项目说明和实际文件。
3. 对上下文中将影响下一步的易变事实做针对性核实。例如，之前的测试通过记录不能证明当前代码仍然通过。

上下文是缩小调查范围的线索。代码、运行结果和用户最新指令发生变化时，修正旧记忆。源码可确认“现在实现了什么”；实现是否符合长期约束仍需结合明确的用户决定判断，不能看到代码冲突就擅自改掉约束。

### 工作与保存

按正常开发流程工作。只有出现会改变后续接续的事实、关键决定、阻塞或切换点，才更新相关内容；不在每次工具调用后写记录。

准备暂停、切换任务、交接或结束本轮时，整理一次当前状态。长任务中重要进展已经足以改变接续方式时，应及时留下，而不是始终等到最终答复才保存。

### 完成与清理

先把确实需要长期维护的内容放进正确文档或长期有效区域，再删除完成任务的小节和失效信息。完成的依据是工作和必要验证实际完成，写过记录或执行过命令都不构成完成证明。

若还留有用户认可的未完成工作，保留其当前状态和下一步；新发现但尚未采纳的可能改进不自动形成任务清单。删除完成小节不创建 archive、closeout、快照、搬迁登记或压缩备份。

### 五个边界，使用同一模型处理

| 场景 | 行为 |
|---|---|
| 一个会话内完成的小任务 | 没有长期新信息时，上下文写入为零；有正式文档变化才更新对应文档 |
| 意外中断或上下文丢失 | 从最近已保存的状态恢复，再检查实际文件；不承诺恢复最后一次保存之后的全部思考 |
| 从任务 A 切换到 B | 保存 A 的必要接续信息，给确实需要跨会话的 B 增加同级小节；不覆盖 A，不增加 active-task 文件 |
| 多 Agent 协作 | 同一工作区由主会话整合上下文，子代理回传必要结果；不同工作区沿用文件差异审查，不引入锁、事件流或合并服务 |
| 任务需要大型设计稿或其他交付物 | 文件作为项目文档独立存在，上下文只写相关结论的落点和接下来要读的部分 |

单文件方案适合个人开发和由主会话协调的 Agent 任务，不提供多人同时编辑的调度保证。某个 Skill 的使用不能自动保证所有并行 Agent 都遵守同一个写入协调约定；修改前需阅读已有内容，只更新自身相关小节。

### 控制读取成本和增长

- 常规恢复时，本工具额外引入的上下文文件读取为 **0 或 1 个**。这不包含宿主加载 Skill、项目指令，以及执行任务实际需要读取的代码与文档。
- 首版 Skill 正文目标不超过约 **1500 个字符**；以实际交付文本统计，不把参考文件藏到预算之外。
- 单个未完成任务通常 **5–10 行**；常规项目的上下文以 **约 1500 个中文字符量级**为整理目标。这些是写作预算，不是截断上限或 CI 门禁。
- 内容增长时，先删除失效/重复项，缩短已被替代的表述，再把独立交付物放回其正确文档。不能为了凑字数丢弃未解阻塞，也不能把溢出文本原样转存成记忆档案。
- 不引入定期扫描、过期时间、自动摘要、向量检索或 token 审计机制。只有实际更新或读取时发现内容需要整理，才整理它。

## 5. 独立 Skill 的具体设计

新名称为 `worklog`，目录为 `skills/worklog/`。不保留旧 `planning` 别名。Skill 文件是唯一行为说明，不依赖包内模板、参考手册、脚本、配置或外部服务。

用户可以复制整个 `skills/worklog/` 目录到所用 Agent 支持的 Skill 位置。即使没有自动 Skill 加载机制，也可以将该文件作为本次任务说明交给具备文件读写能力的 Agent。两种用法都无需 Node、npm、Git 或项目初始化。

技能内容参考 `skill-creator` 的原则：只保留会改变 Agent 行为的非显然规则；完整内容放在一个 `SKILL.md`，不添加没有实际用途的 scripts、references、assets 或 UI 元数据。

以下为待实施正文草案，仅嵌入本方案；本轮不生成或安装实际 Skill：

```markdown
---
name: worklog
description: 维护项目文档和少量长期上下文；用于跨会话任务、保存进度与已确认约束，以及恢复中断的工作。
---

# 项目上下文

用普通项目文件维护当前有效信息。默认在项目根目录按需使用 CONTEXT.md；用户指定已有上下文文件时使用那一份。

## 开始

读取已有上下文，再按本次任务需要读取相关项目文件。文件不存在时直接工作，首次有必要保留的信息才创建。易变事实从实际文件或运行结果核实；发现旧说法失效时更新它。若实现和已确认约束冲突，按用户当前目标处理，未定事项保留为问题。

## 文档与记忆

已有文档是正确落点时直接更新原文，不复制成第二份。新文档只用于确实需要独立阅读或交付的内容；上下文按需引用相关路径和章节。

CONTEXT.md 可分“长期有效”和“未完成任务”两节，空节省略。长期信息只保留后续仍需知道、难以从现有文档或代码恢复的背景、已确认约束与关键决策，带上必要原因。用当前说法替换旧说法，不追加历次版本。

## 继续工作

未完成任务只写目标、当前落点、必要决定及原因、未解问题和具体下一步。只保留影响接续的验证结果与尚未验证范围，不写命令输出、过程日志或可随时重新读取的仓库信息。

出现会改变接续的进展、决定或阻塞时更新相关小节；暂停、切换或交接前整理。多个未完任务使用同级小节，先读已有内容，保留其他任务。协作时由主会话整合必要结果。

## 结束

把有长期价值的内容更新到正确落点，再删除已完成任务和失效信息；整个文件为空时可删除。保留仍获认可的未完成工作，不自动建立未来需求清单。不归档、不写完成台账；一次做完且没有长期新信息的任务无需记录。
```

README 只负责项目用途、获取与使用方法、一个短接续示例和能力边界，不再复制上述完整规则，也不另发一套手册和模板。

## 6. 新仓库形状及每个文件的必要性

实施完成后的常驻仓库目标如下；当前仍是原工作树加本方案，尚未执行图中任何删除：

```text
worklog-kit/
├── README.md
├── LICENSE
├── AGENTS.md
├── .gitattributes
└── skills/
    └── worklog/
        └── SKILL.md
```

| 文件 | 必要性及范围 |
|---|---|
| README.md | 唯一产品入口；帮助新用户理解全部工作流，不保存历史发布状态 |
| LICENSE | 保留现有许可及版权声明；不随产品删减改写已有归属说明 |
| skills/worklog/SKILL.md | 产品唯一行为实现；可单独复制使用 |
| AGENTS.md | 已有维护者协作约束，作用于开发本仓；不复制给使用者，不自动修改用户的协作规则 |
| .gitattributes | 保留现有单行文本换行约定，使跨平台编辑保持一致 |

本方案在实施期间继续作为交付与审查依据，因此会暂时多出这一份设计文档。实施完成后，仍有效的使用说明进入 README、行为规则进入 Skill；本文不被列为使用者或 Agent 的常规必读材料。后续确有必要保留的独立设计结论可留在项目文档中，不为留存方案而建立档案机制。

本仓如果在重做期间发生实际交接，可以按新 Skill 建立自身的 `CONTEXT.md`，只记录本次重做的有效待办；不导入旧项目记忆。它也是按需文件，不属于产品分发必需品。

新产品没有 `package.json`、`bin`、`src`、运行期依赖、构建或消费者 CI 注入。生产可执行代码目标是 **0**。使用者获得 Skill 文件即可使用，不需要 npm 安装路径；现有远端 npm 历史版本不在本轮处理范围内，也不提供兼容入口或迁移程序。

## 7. 当前项目与删除范围

已读取背景方案，并由指定模型子代理只读盘点实际命令、代码、文档、Skill、模板和隐藏配置。现状判断依据工作树；没有用旧文档中记载的“验证成功”冒充本轮运行结果。

核实的核心问题：

- `bin/worklog.mjs` 暴露 17 个顶层命令，涵盖建档、治理、归档、诊断、迁移与 Skill 分发。
- `src/check-index.mjs` 与配置、目录职责表共同维护目录一致性；`src/check-docs.mjs` 承担 frontmatter、收口及文档关系规则。

## 8. 实施顺序

不把旧系统分阶段改造成新模型，不安排兼容过渡期。实施按以下顺序准备，在一个完整交付批次内形成新产品：

1. **记录实施边界。** 再核对工作树与最新用户指令。当前已存在 `CLAUDE.md` 删除、`src/selftest.mjs` 和 `tools/token-audit/selftest.mjs` 修改、`AGENTS.md` 及既有 Review 未跟踪文件；本轮未触碰这些变化。实施时不做 reset、强制清理或覆盖。已授权的新设计淘汰项按清单删除，其他用户变化保留。
2. **先删旧产品机制。** 删除前核实绝对路径限定在本仓；按第 7 节移除运行时、配置、模板、旧 Skill、旧治理与分发机制。保留本方案、许可及维护者指令。
3. **直接编写新 Skill 和 README。** 落实第 5 节正文；README 用最短路径说明获取 Skill、开始工作、保存必要信息和恢复。整理少量仓库配置。不留空目录、待实现命令或将来扩展接口。
4. **清理旧文档。** 删除已退役内容和对旧命令的操作指引。不为了让旧校验器通过而补 metadata 或修改新模型。
5. **做新链路验证。** 按第 9 节在干净临时项目中验证 Skill 独用和上下文接续，修正真实暴露的问题，再审查最终差异。

这个交付批次不包括安装到维护者个人目录、远端发布、修改 npm 历史包或任何私公仓同步。没有这些动作，新产品核心链路也应能完整使用。

首版不写通用测试框架。产品已无可执行代码，验证对象是 Skill 的可发现性、独立性和实际引导出的文件行为；若演练暴露明确且重复的机械错误，再针对真实问题判断是否需要少量自动检查。

## 9. 验收：以使用结果为准

### 新链路必须实际演练

演练使用临时的普通文件项目，Skill 可直接读取；不安装 Node、不建立 npm 项目、不要求 Git、不加载本仓模板或背景方案。恢复演练的后续 Agent 只得到用户继续工作的请求、Skill 和临时项目文件，不得到前序会话推理。

| 场景 | 通过条件 |
|---|---|
| 只复制 Skill | 没有任何其他产品文件和服务也能执行保存与恢复；引用零缺失，零 CLI 调用 |
| 空白项目的一次性小任务 | 任务完成且没有长期新信息时，不创建 CONTEXT、任务目录或完成记录 |
| 首次长任务暂停 | 只新建一份 CONTEXT；另一会话能说清目标、当前落点、关键理由、未完事项及具体下一步 |
| 决策已经在 README | 更新 README 原文，上下文按接续需要只留引用，不复制决定正文 |
| A 暂停后开始 B | A 的必要信息仍在；B 使用同文件中的对应小节，没有第二份任务文件或中心状态 |
| 决策变化与任务完成 | 旧说法被替换；完成小节消失；必要长期事实仍在；不产生 archive、closeout 或追加式完成日志 |
| 上下文与实际代码不同 | 后续 Agent 识别与本次工作相关的变化并修正记忆；不把旧测试通过当作当前验证结果 |
| 大型交付物 | 独立保存有实际用途的文档；上下文足以定位相关部分，恢复不要求全量历史阅读 |
| 连续任务重复使用 | 以三个前后接续任务检查，已完成内容被淘汰；体积随有效信息变化，不随任务次数单调累加 |

### 静态与交付检查

- 对实际新 Skill 做 frontmatter、名称和无未完成占位检查；只验证 Skill 元数据，不给 CONTEXT 引入 schema。
- 检查 Skill 所有指引可由普通文件读写完成，没有 CLI、初始化配置、额外模板、手册或服务依赖。
- 从新产品入口和 Skill 检查内部引用有效、示例一致。旧名称若仅出现在本设计的删除说明中，不算兼容残留。
- 审查仓库最终树，确认没有旧命令转发、迁移、baseline、版本 schema、事件模型、索引生成和历史复制脚本。
- 检查实际交付目录可独立取得，单独 Skill 与完整仓库使用同一份 Skill 原文，没有第二套行为实现。
- 最终报告记录实际观察到的新增文件数、恢复读取数和文本体积；不根据估算器声称 token 节省百分比。

### 首版量化边界

| 项目 | 目标 |
|---|---|
| 产品生产命令 | 0 |
| 生产可执行代码、运行期依赖、后台服务 | 0 |
| 消费项目新增的配置、索引、manifest、数据库 | 0 |
| 消费项目默认新增文档目录、任务目录 | 0 |
| 本工具维护的上下文文件 | 按需 0 或 1 |
| 已完成任务的额外持久化记录 | 0 |
| Skill 的必需文件 | 1 个 SKILL.md |
| 普通恢复所需额外上下文文件读取 | 0 或 1；项目正常阅读另计 |

以上是待实施的验收目标，不是本轮已经测得的性能或行为结果。旧 17 套自检及其历史成功记录不作为新产品验收条件。

## 10. 最后的删除检查

再按“如果今天第一次实现，还能删除什么”检查：

- CLI init 只创建一个文件，可以删；resume 只读一个文件，可以删；check 不能判定语义价值，也删。
- 两个记忆文件可以合为一个，删独立任务态文件。
- 模板内容可以直接从实际信息写起，删模板文件与模板管理。
- 候选 ID、处置表、归档、索引和工作线，都是为旧模型同步而存在，全部删。
- Skill 已经自包含，删安装器、引用路由、参考目录和运行时。
- README 能说明全部使用方式，删上手手册、收口手册、维护总表和重复规格。
- 格式不能替代有效上下文，删形式化门禁，不再为它积累状态和测试框架。
- 没有真实未完成工作或长期补充信息时，连 CONTEXT.md 也无需存在。

最后保留的是：一份可独立使用的 Skill，项目本来就需要的文档，以及必要时的一份当前上下文。每增加一个文件、命令或机制，都必须重新证明它解决了普通文件与这份 Skill 无法直接解决的当前问题。
