# worklog — 任务接续与记录

用 state.md 定位工作，用 details.md 保存执行依据与证据。本 Skill 可单独复制使用，不依赖 CLI。

## 读取入口

复用当前上下文中已读、亲自写入或派工消息附带的原文。只有所需材料缺失（含压缩、截断）、已知外部修改或具体版本冲突时，才补受影响章节；新消息、继续执行或切换角色本身不触发重读。

首次进入或恢复任务时，缺少定位信息才读 state 的「当前」「进度」「下一步与阅读」。未指定任务时从 `docs/todo.md` 选工作，无索引则浏览任务目录。下面列的是需要掌握的材料，已有内容即满足，只补缺项：

| 角色 | details 材料与说明 |
|---|---|
| 探索 | 目标与验收，加已存在的共同约束、探索结果；[探索说明](references/exploration.md) |
| 设计 | 目标与验收、探索结果、共同约束、当前设计；[设计与派工](references/design.md) |
| 施工 | 共同约束、当前设计、指定单元全文；[施工说明](references/implementation.md) |
| 验收 | 目标与验收、共同约束、当前设计；单元验收加该单元全文，整体验收加各单元的目标与验收、依赖与必读、当前结果；[验收说明](references/acceptance.md) |

项目提供 `worklog-kit` 时，用 `context` 提取缺少的材料：

```sh
worklog-kit context <任务> --section 当前设计 --section t2-单元标题
worklog-kit context <任务> --unit T2
worklog-kit context <任务> --role implement --unit T2
```

`--section` 可重复，按 details.md 锚点选完整章节；`--unit` 补整个单元；`--role` 取完整角色读集。选章与角色、单元模式互斥，工具不记忆已读内容。无 CLI 时按标题边界取完整章节、保留子节；仅当所需内容覆盖全文时才输出全文。

选中章节的显式必读只展开一层：`必读：[名称](相对路径.md#锚点)`，一行一条本地 Markdown 链接；同文件可写 `#锚点`，已完整包含的片段不重复，普通链接按需打开。源码与测试给路径及所属根目录。

## 记录位置

任务放在 `docs/tasks/YYYY-MM-DD-可读名称/`；名称跟随会话主要语言，与文件标题一致，用户指定优先。state 是本任务唯一进度入口，只留动作、状态、缺口与指针；details 保存设计和证据，共享章节只放跨单元约定，专属方案归单元。执行边界以用户最新指令为准，记录与格式检查不构成授权。

创建或修复结构时读 [state 模板](templates/state.md)与 [details 模板](templates/details.md)，按其中字段、状态和四组单元标题填写；无项写「无」，未决写「待定」，探索与设计不必填满施工材料。

## 何时写回

单元或完整工作轮结束，先保存证据、原位更新单元「当前结果」，再改变化的 state 字段；交接、中断或实质阻塞时保存最小状态。没有新事实不重写。受派执行者按验收条件做最低充分验证，回传改动、验证、缺口与文档影响，由主会话统一落盘。

结果注明适用版本、环境、证据与未验证项，多轮实测保留样本、配置与可比条件；旧结果和失败证据按需放已有报告或任务内 references，以普通链接保留，未解决失败留当前缺口。行为变化时同步受影响的说明；主题与索引只在现状、工作选择或入口变化时更新。

文档落点、全局进度、断链与知识沉淀按[治理说明](references/governance.md)处理；需建索引或主题时用 [todo](templates/todo.md)、[topic](templates/topic.md) 模板。`check` 检查结构与引用，`init` 导出 Skill。
