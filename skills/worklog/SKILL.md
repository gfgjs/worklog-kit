# worklog — 任务中枢与文档治理

本文件是当前任务记录规范的入口。任务记录、角色读集与交接纪律以本文为准；命令契约与格式细节见使用说明。施工单元按「目标与验收、方案与范围、依赖与必读、当前结果」四组材料组织，日常读写不再随历史轮次增长。

## 记录位置

任务默认落在项目的 `docs/tasks/<日期-可读名称>/`：

| 文件 | 装什么 | 权威范围 |
|---|---|---|
| `state.md` | 目标摘要、阶段、执行边界、进度表、下一步与阅读 | **本任务执行进度只在这里** |
| `details.md` | 目标与验收、探索结果、共同约束、当前设计、各施工单元 | 细节与证据 |

目录名 = `YYYY-MM-DD-可读名称`；T1、T2 等编号只在该任务内有效。文件存在不代表获准施工，也不代表设计已确认。当前结果写在对应单元里，不再设全局「执行结果」章节。

## 阶段与状态

`阶段：探索 | 设计 | 施工 | 待验收 | 完成 | 已取消` 写在 state.md 的「当前」节。暂停与阻塞用同节的说明字段表达，不另造阶段组合。单元状态用 `未开始 | 进行中 | 待处理 | 已自检`。已自检不等于已验收；取消写「已取消」和原因，不冒充完成。

## 角色路由

- 未指定工作：先读 `docs/todo.md`，再选相关主题章节或任务 state；没有 todo 时浏览任务目录。
- 已指定任务：读该任务 state 的「当前」「进度」「下一步与阅读」，再按角色读**一份**参考；details 按下表章节读，不整篇加载。
- 询问全局进度或全部待办：读已指定的全局说明与相关主题，用 `context --list` 枚举未完成任务并按需读 state；无 CLI 时浏览任务目录。todo 只是人工选择，不能据它宣称全局完成。

| 角色 | 何时用 | 读什么 |
|---|---|---|
| 探索 | 目标清楚，需要摸清现状 | state + details 的「目标与验收」，加已存在的「共同约束」「探索结果」→ [references/exploration.md](references/exploration.md) |
| 设计 | 需要定方案、拆单元、改接口 | state + 「目标与验收」「探索结果」「共同约束」「当前设计」→ [references/design.md](references/design.md) |
| 施工 | 按已定方案实现指定单元 | state + 「共同约束」「当前设计」+ 指定单元的四组材料；再展开这些所选片段的显式必读 → [references/implementation.md](references/implementation.md) |
| 验收 | 检查交付是否达标 | state + 「目标与验收」「共同约束」「当前设计」；指定单元时加该单元全文，整体验收时加全部单元的目标与验收、依赖与必读、当前结果 → [references/acceptance.md](references/acceptance.md) |

涉及文档落点、有效性、断链或知识沉淀时加读 [references/governance.md](references/governance.md)。仅在创建或修复结构时读相应模板：[state](templates/state.md)、[details](templates/details.md)、[todo](templates/todo.md)、[topic](templates/topic.md)。主题按需建立，优先复用已有正文。

## 单元

施工单元围绕可观察结果拆分，写成 `## T1 <标题>`，其下四个三级标题：

- **目标与验收**：该单元要交付的可观察结果与判定条件。
- **方案与范围**：单元内的实现选择、接口与明确不做的范围。
- **依赖与必读**：单元前提与专属必读；共享必读留在公共章节，不重复。
- **当前结果**：按验收条件写当前结论、适用版本或环境、证据与缺口；只维护当前有效结论，不逐轮追加。

通用回交与回传规则归角色说明；单元特有的偏差条件并入「方案与范围」，不逐单元重复通用几项。单元专属设计与依赖放该单元，不放公共章节；公共章节会随每个单元加载，把详细设计留在公共章节再补单元指针不会减少读取。取消全局「执行结果」：原始过程、旧结果与失败证据放已有报告或任务内 `references/`，用普通链接按需读取；当前缺口在单元的「当前结果」里留指针。长历史与失败证据必须可达，不要求每轮内联追加。

## 共同规则

- **授权决定施工。** state.md 的「执行边界」写清本次允许做什么。处于只讨论阶段时，任务文件存在或方案完整都不构成施工许可；方案写入文件也不自动等于获准执行。
- **格式标记不等于批准。** 章节、必读、单元齐全只说明材料完整，工具不判断授权。以用户最新指令为准；指令与记录冲突时按用户执行并回写记录。
- **本任务执行进度只在 state.md。** details.md 不维护第二份进度表；每项事实只保留一处正文，各章节维护当前有效结论，变更才更新。历次实验与失败证据仍可查，按需链接已有来源；确需保留的长材料放任务内 `references/`，单元「当前结果」留结论与指针。先写详情与证据，再更新 state 摘要；主题、todo、README 仅在现状、工作选择或入口变化时更新。
- **state 只留短进度指针。** 「当前」「进度」「下一步与阅读」只放当前动作、状态、缺口与必要指针，不抄证据、不复述设计。
- **单元「当前结果」按验收条件维护。** 更新既有结论而不是追加施工日记；多轮实测保留版本、样本、配置与可比条件，旧版本行与失败记录保留、按需链接，不用最新成功覆盖；当前摘要指出尚未解决的失败。
- **按工作轮写盘。** 单元或完整工作轮结束时集中写详情、再更新变化的 state 字段；交接、中断或实质阻塞时随时把最小状态写回 state，不要求完整总结；短暂等待与轮询留在对话里，没有新事实就不重写文件。
- **必读用独立行标注：** `必读：[名称](相对当前文件的路径.md#锚点)`，一行一个，只标 Markdown 片段。源码与测试给路径指针（注明相对哪个根）。同文件 `#锚点` 与带文件路径锚点都支持。只展开一层，且所选章节已完整包含的片段不重复注入；引用里的引用不递归展开，依赖须在任务中显式声明。历史结论与长证据用普通链接，不自动展开。
- **按需接续。** 同一上下文里已加载且仍有效的材料继续使用，不重读：同一单元连续施工不重读，切换到另一单元只补读该单元及其一层必读。切换角色时按角色路由补齐尚未加载的角色参考与必需章节。压缩换会话后先读 state.md 定位当前单元，再按角色路由补读该单元材料；恢复不自动整读 Skill 与 details。阻塞由外部条件引起且条件未变时，不再新开诊断轮。
- **无项写「无」，未决写「待定」。** 不留占位符，不把推测写成用户决定；探索与设计阶段允许「待定」与尚无施工单元，不要求填满整套模板。
- **重大偏差回交。** 接口或行为与方案前提不符、需扩大范围、需新增依赖、验收矛盾，或连续尝试没有新增有效信息时，停止受影响单元并按角色说明回传期望、实际、证据与需要的决定。
- **改动即维护文档。** 行为变了就更新受影响的现行说明，避免复制第二份规范；长期结论提升到主题文档，任务详情只留摘要与指针。

## 工具（可选，非必需）

项目若提供 `worklog-kit`：`context` 按角色抽取材料，`check` 检查结构与引用问题，`init` 把本 Skill 导出到指定目录。有工具时优先用 `context` 取材料；没有工具时按上面的读取规则手工读同样的章节，一层必读与展开范围保持一致。本 Skill 目录单独复制后不依赖任何 CLI。

采用 CLI 时，使用支持四组单元与 `accept --unit` 的工具版本。旧八项任务须先整理为四组材料，将全局执行结果归入对应单元；没有匹配工具时，按本文用文件能力完成读取与交接。

## 最低验证

单元完成后按风险做最低充分验证，证据写进该单元的「当前结果」，state.md 只留结果指针。环境不支持的验证写「未验证」和原因，不得改验收标准来制造通过。
