# 验收角色

按条件、差异与证据判断交付是否达标。验收者可以是用户本人、被指定的高级模型，或按用户预先授权的明确检查结果判定。

## 读什么

state.md，加 details.md 的「目标与验收」「共同约束」「当前设计」，以及相关 diff 与实际运行结果。

不论是否指定单元，都读共享的「目标与验收」「共同约束」「当前设计」。指定单元时再加该单元的四组材料全文；不指定时为整体验收，改为加全部单元的目标与验收、依赖与必读、当前结果，并按任务给出的方案定位打开相关方案。

不默认注入全部探索历史，也不整篇加载 details；长原始证据按普通链接按需打开。摘要只是入口：沿「当前结果」的依据指针补读相关单元设计、适用共同约束及约束片段，核对实际证据，不加载无关单元；不能仅凭摘要判定通过。补读是验收责任，用文件能力完成，不因有无 CLI 而改变。

## 怎么做

- 核对待验收条件与「当前结果」证据是否对得上。「已自检」是执行者的结论，要用证据复核。
- 抽查关键行为或差异，有具体疑点才扩大范围；没有疑点不做全仓探索。
- 未验证项按未验证对待，旧结果不能证明新改动通过。
- 核对与本次相关的实测行，确认此前失败的轮次是否真的解决；版本、样本或配置不同的行，结论不能互相顶替，长历史不整段重读。
- 不通过的回具体单元或设计决定：写清期望、实际、证据与要谁决定。

## 结论

- 通过：更新 state.md 为 `阶段：完成`，保留简短结果与必要文档链接，并按 [承接与回收](governance.md#承接与回收) 核对成果落位、剩余事项与索引回收，修复受影响的证据链接。
- 未通过：阶段回到「施工」或「设计」，state.md 留阻塞指针，详情写进对应单元的「当前结果」缺口处。
- 用户尚未选择验收方式时保持 `阶段：待验收`，把证据与未验证项摆清楚，不自动判定完成。
