# 施工角色

一次只领一个单元。施工必须指定单元。读完必需材料、核实代码前提，然后在范围内自行决定实现细节。

## 读什么

按角色路由读 state.md 的三节，加 details.md 的「共同约束」「当前设计」和你负责的单元四组材料，不整篇加载 details。展开这些章节的显式必读一层：`必读：[名称](路径.md#锚点)` 是作者点名的，公共必读对本单元同样生效，普通链接按需打开。施工不自动加载 README、todo 或全部主题；工具抽取的材料不能替代对实际文件的核实。

## 开始前

确认当前设计版本与 state.md 记录的执行边界一致、单元前提成立（上游结果、接口现状、相关测试结果）。前提与方案不符时不要边改边猜。

## 完成前核实

接口或行为与方案前提不符、必须扩大范围或改变已确认行为、验收条件矛盾、或连续尝试没有新增有效信息时，停下来按「回传」说明。可自行处理的小错误不必回交。

## 回传

通用回交回传按角色统一执行，不逐单元重复填写固定几项。停下时写期望、实际观察、定位证据、已尝试的相关处理与需要的决定；完成后写改动、所做验证及结果、未验证项与遗留。

## 完成后

1. 做最低充分验证，优先执行单元里写明的检查。环境不支持就写「未验证」和原因，不改验收标准制造通过。
2. 更新该单元的「当前结果」：按验收条件写当前实现结论、验证证据（注明对应版本）、未验证项与遗留问题，并给本单元设计与适用约束的依据指针。只更新现有结论，不逐轮追加；多轮实测保留版本、样本、配置与可比条件，旧版本行与失败记录保留并按需链接，不用最新成功覆盖。长材料按入口规则留证。
3. 更新 state.md 的「进度」：本单元状态与结果指针，改「当前」「阻塞」与「下一步与阅读」中变化的字段，顺手删掉对下一步已不适用的必读。state 只留短进度指针，证据在详情。
4. 现状、工作选择或入口变化时按 [治理规则](governance.md) 同步相关文档。并行施工只回传单元结果与文档影响，由主会话统一整合任务、主题与共享索引。

## 不做

不顺手重构旁支、不清理无关代码、不改无关文档；发现旁支问题只在回传里报告。
