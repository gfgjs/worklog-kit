# 施工角色

一次只领一个指定单元。沿用已有材料，按 Skill 入口补齐缺项、核实代码前提，然后在范围内自行决定实现细节。

## 开始前

沿用已掌握的设计版本与执行边界；材料缺失或出现入口规定的变更、冲突时，只补相关章节。按本单元需要核实上游结果、接口现状和相关测试等代码前提，复用已有核实证据。遇入口规定的重大偏差回交，可自行处理的小错误在单元内解决。

## 回传

停下时写期望、实际观察、定位证据、已尝试的相关处理与需要的决定；完成后写改动、所做验证及结果、未验证项与遗留。

## 完成后

1. 做最低充分验证，优先执行单元里写明的检查；未验证项如实说明原因。
2. 按入口的记录规则更新该单元「当前结果」，给出本单元设计与适用约束的依据指针；证据注明对应版本，长材料链接保留。
3. 更新 state 中变化的字段：本单元状态与结果指针、当前动作、阻塞及下一步；清掉对下一步已不适用的必读。
4. 现状、工作选择或入口变化时按 [治理规则](governance.md) 同步相关文档。并行施工只回传单元结果与文档影响，由主会话统一整合任务、主题与共享索引。

## 不做

不顺手重构旁支、不清理无关代码、不改无关文档；发现旁支问题只在回传里报告。
