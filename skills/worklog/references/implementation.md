# 施工角色

一次只领一个指定单元。派工消息已附执行原文和来源时，直接据此核实代码、完成工作并回传结果，由主会话维护记录；独立接续时只补缺少的材料，在范围内自行决定实现细节。

## 开始前

按本单元需要核实上游结果、接口现状和相关测试，复用已有证据。接口或行为不符、需要扩大范围或新增依赖、验收矛盾，或连续尝试没有新增有效信息时，回交受影响部分；小错误在单元内解决。

## 回传

停下时写期望、实际观察、定位证据、已尝试的相关处理与需要的决定；完成后按验收条件做最低充分验证，优先执行单元写明的检查，回传改动、验证结果、未验证项与原因。

## 独立接续时的记录

1. 按入口的记录规则更新该单元「当前结果」，给出本单元设计与适用约束的依据指针；证据注明对应版本，长材料链接保留。
2. 更新 state 中变化的字段：本单元状态与结果指针、当前动作、阻塞及下一步；清掉对下一步已不适用的必读。
3. 现状、工作选择或入口变化时按 [治理规则](governance.md) 同步相关文档。

## 不做

不顺手重构旁支、不清理无关代码、不改无关文档；发现旁支问题只在回传里报告。
