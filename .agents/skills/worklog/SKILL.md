# worklog — 任务中枢与文档治理

用 state.md 定位当前工作，用 details.md 保存执行依据与证据。本 Skill 可单独复制使用，不依赖 CLI。

## 读取入口

默认复用当前上下文中已读或亲自写入的材料。新消息、继续执行、切换角色或模型本身不触发重读。

所需原文缺失（包括被压缩或截断）、已知材料被其他执行者修改，或出现具体版本冲突时，只补读受影响章节；无需为确认有效性例行检查文件或版本。

| 本次情形 | 读取动作 |
|---|---|
| 查询进度 | 先用已有状态；缺失时只读 state，解释具体结果时再补对应单元 |
| 同单元继续 | 直接工作；收到材料变更时只补受影响章节 |
| 同上下文换单元 | 沿用已有共享材料，只补目标单元四组材料及其缺少的一层必读 |
| 换角色 | 沿用已有材料，只补该角色缺少的说明、章节及其一层必读 |
| 首次进入任务或恢复缺失上下文 | 从 state 的「当前」「进度」「下一步与阅读」定位当前单元，再补角色缺项 |

角色表列出工作需要掌握的材料，已有内容即满足要求，只读取缺项：

| 角色 | 需要掌握的 details 章节与角色说明 |
|---|---|
| 探索：摸清现状 | 「目标与验收」，加已存在的「共同约束」「探索结果」；[探索说明](references/exploration.md) |
| 设计：定方案、拆单元 | 「目标与验收」「探索结果」「共同约束」「当前设计」；[设计说明](references/design.md) |
| 施工：实现指定单元 | 「共同约束」「当前设计」+ 指定单元四组材料；[施工说明](references/implementation.md) |
| 验收：检查交付 | 「目标与验收」「共同约束」「当前设计」；指定单元加该单元全文，整体验收加全部单元的目标与验收、依赖与必读、当前结果；[验收说明](references/acceptance.md) |

读取 details 时，已知目标章节可合并读取，按标题边界输出完整片段，并补齐缺少的一层必读。标题未知时才定位标题；本次所需内容覆盖全文时可直接全文读取。手工取材可在命令内部读取全文，只向模型输出选中章节；单元内的小节随单元一起保留。

无 CLI 时可用以下 PowerShell 示例，替换路径和目标二级标题；围栏内的示例标题保留为正文。所选章节的一层显式必读按下文规则补齐。

```powershell
$wanted = @('共同约束', '当前设计', 'T1 单元标题')
$emit = $false; $fence = ''
Get-Content -LiteralPath 'docs/tasks/日期-任务名/details.md' | ForEach-Object {
    if ($fence) {
        if ($_ -match ('^ {0,3}' + [regex]::Escape($fence.Substring(0, 1)) + '{' + $fence.Length + ',}\s*$')) { $fence = '' }
    } elseif ($_ -match '^ {0,3}(`{3,}|~{3,})') { $fence = $Matches[1] }
    elseif ($_ -match '^#{1,2}\s+(.+?)\s*#*\s*$') { $emit = $Matches[1] -in $wanted }
    if ($emit) { $_ }
}
```

项目提供 `worklog-kit` 时优先用 `context` 取材：

```sh
# 首次取齐施工材料
worklog-kit context <任务> --role implement --unit T2
# 已有共享材料，只补新单元及其一层必读
worklog-kit context <任务> --unit T2
```

其他角色用 `explore`、`design`、`accept`；`check` 检查结构与引用，`init` 导出 Skill。无 CLI 时按同一读集手工取材。

已有部分材料时，按章节补齐缺项；`--role` 输出完整角色读集，不自动扣除已读内容。

- 未指定任务：先读 `docs/todo.md` 选相关主题章节或任务 state；无 todo 时浏览任务目录。
- 全局进度或全部待办：读指定全局说明与相关主题，用 `context --list`（无 CLI 则浏览任务目录）枚举未完成任务、按需读 state。todo 是人工选择，不能单独证明全局完成。
- 涉及文档落点、有效性、断链或知识沉淀时补读[治理说明](references/governance.md)；创建或修复结构时才读相应模板：[state](templates/state.md)、[details](templates/details.md)、[todo](templates/todo.md)、[topic](templates/topic.md)。

## 记录位置

任务默认落在项目的 `docs/tasks/<日期-可读名称>/`：

| 文件 | 装什么 | 权威范围 |
|---|---|---|
| `state.md` | 目标摘要、阶段、执行边界、进度表、下一步与阅读 | **本任务执行进度只在这里** |
| `details.md` | 目标与验收、探索结果、共同约束、当前设计、各施工单元 | 细节与证据 |

目录名 = `YYYY-MM-DD-可读名称`；T1、T2 等编号只在该任务内有效。state 只放当前动作、状态、缺口与必要指针，设计和证据在 details 维护一份。共享约束与设计只放跨单元约定与共享必读；专属方案与依赖归对应单元，各单元历程按证据规则留存，不汇编进公共设计。

## 阶段与状态

`阶段：探索 | 设计 | 施工 | 待验收 | 完成 | 已取消` 写在 state.md 的「当前」节。暂停与阻塞用同节的说明字段表达，不另造阶段组合。单元状态用 `未开始 | 进行中 | 待处理 | 已自检`。已自检不等于已验收；取消写「已取消」和原因，不冒充完成。

## 单元

施工单元围绕可观察结果拆分，写成 `## T1 <标题>`，其下四个三级标题：

- **目标与验收**：该单元要交付的可观察结果与判定条件。
- **方案与范围**：单元内的实现选择、接口与明确不做的范围。
- **依赖与必读**：单元前提与专属必读；共享必读留在公共章节，不重复。
- **当前结果**：按验收条件原位更新当前结论、适用版本或环境、证据与缺口，不逐轮追加日记。多轮实测保留版本、样本、配置与可比条件；旧版本结果与失败证据继续可达，不用最新成功覆盖。

通用回交与回传规则归角色说明；单元特有的偏差条件写进「方案与范围」。原始过程、旧结果与长失败证据放已有报告或任务内 `references/`，用普通链接保持可达；尚未解决的失败在「当前结果」留缺口与指针。

## 共同规则

- **授权决定施工。** state 的「执行边界」记录用户允许的动作；文件、完整方案与格式检查都不构成授权。以用户最新指令为准，冲突时依指令执行并回写记录。
- **按工作轮写盘。** 单元或完整工作轮结束时先保存证据、更新详情，再更新变化的 state 字段；交接、中断或实质阻塞时及时保存最小状态。短暂等待与轮询留在对话里，没有新事实就不重写文件；外部阻塞条件未变时不新开诊断轮。
- **必读用独立行标注：** `必读：[名称](相对当前文件的路径.md#锚点)`，一行一个，只标 Markdown 片段。源码与测试给路径指针（注明相对哪个根）。同文件 `#锚点` 与带文件路径锚点都支持。只展开一层，且所选章节已完整包含的片段不重复注入；引用里的引用不递归展开，依赖须在任务中显式声明。历史结论与长证据用普通链接，不自动展开。
- **无项写「无」，未决写「待定」。** 不留占位符，不把推测写成用户决定；探索与设计阶段允许「待定」与尚无施工单元，不要求填满整套模板。
- **重大偏差回交。** 接口或行为与方案前提不符、需扩大范围、需新增依赖、验收矛盾，或连续尝试没有新增有效信息时，停止受影响单元并按角色说明回传期望、实际、证据与需要的决定。
- **改动即维护文档。** 行为变了就更新受影响的现行说明；长期结论提升到已有主题或说明，详情只留引用。主题、todo、README 仅在现状、工作选择或入口变化时更新。
- **验证以证据为准。** 单元完成后按风险做最低充分验证，证据写进「当前结果」。环境不支持就写「未验证」和原因，不得改验收标准制造通过。
