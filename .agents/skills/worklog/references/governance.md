# 文档治理

任务记录之外的文档如何保持可信。涉及文档落点、有效性判断、断链或知识沉淀时读本文件。

## 入口与落点

- 文档入口回答「哪个问题去哪里看」。文档少时直接列在项目 README，多时用项目文档目录的 README。入口只列主要落点，不枚举所有文件，也不镜像任务进度。
- 同一事实只在一处维护正文，其他位置写短摘要加指针。发现冲突时点明冲突点与依据，不自动以最新日期或当前代码覆盖用户已确认的约束。

## 工作索引与主题

- `docs/README.md` 只回答「去哪里看」，`docs/todo.md` 只回答「先做什么」，均以一屏左右为写作目标，不做长度门禁或截断。
- todo 固定「当前重点」「下一批」「其他事项」三组，只写短名称加相对链接，空组写「无」。前两组指任务 state 或已选中的主题事项锚点，同一事项不重复；其他事项只给主题入口，可以覆盖当前任务所在主题。不写背景、阶段、进度或完成统计，也不保证全量登记。
- `docs/topics/<主题>.md` 按需建立，已有产品规划、指南或约定直接复用。建议「当前现状、开放事项、相关任务、依据与约定」四节，按真实需要取舍，不造空表。现状原位更新，事项用稳定标题，写问题或期待结果、来源、启动条件或待决定信息，不预写实现与进度。
- 全局现状必须选定一处正文，优先指定已有产品规划章节，无合适落点才建 `docs/topics/项目推进.md`。写当前总目标、阶段成果与缺口、跨主题依赖和主题链接，不维护第二份任务进度表。
- 跨主题问题选一处正文，其余引用。未核实发现留 details；已确认值得后续处理即可进主题。主题过长时按真实领域拆分或移出长设计，改标题与落点时同步活链接。
- 不为每个待办建文件，不建全局编号、固定元数据、工作线注册表、完成总库或自动摘要。无需接续的小改不强制建任务或主题。

## 承接与回收

事项立项后保留原锚点，已承接范围改为短名称加任务指针，需求、验收与执行进度只在任务里。可由多个任务部分承接，剩余范围继续写在原事项下。

| 事件 | 主题 | todo |
|---|---|---|
| 任务完成且事项全部解决 | 成果更新到当前现状，删除整个开放条目 | 撤下该事项工作选择条目，不改指结果页 |
| 任务完成但仍有剩余范围 | 只更新已解决成果，保留剩余问题、启动条件与后续任务指针 | 撤下已完成任务条目；仍被选中的剩余事项保留或改指主题锚点 |
| 暂停或取消 | 只要仍可能继续就保留开放事项，写明再启动条件 | 按能否继续决定保留与分组，保留时指向可继续的事项或任务 |
| 明确放弃 | 移除开放事项，必要时在依据与约定留结论与原因 | 撤下该事项条目 |

验收范围内未完成的内容不能移回主题来制造任务完成。删除锚点时，有证据价值的来源引用改指当前现状或任务结果；无关条目与仍有导航价值的主题入口保留，空组写「无」。相关任务只保留仍在进行或需要反查的指针，历史过程留任务目录。

## 更新与读取

日常只维护 state 与 details；现状、工作选择、入口实际变化时才同步主题、todo、README。先写事实与证据，再更新 state 摘要，最后按影响更新索引，不为写回扫描全仓。并行单元回传结果，由主会话统一整合共享索引与主题。

普通单任务施工直接进 state。全局问题才读全局说明与相关主题，并用 `context --list`（无 CLI 则浏览任务目录）枚举未完成任务、按需读 state；todo 不能单独证明全局完成。索引中的普通链接及看似必读的内容都不自动展开，主题只读相关章节。

## 三种适用性

- **草案**：尚未确认或实施的提案，写明哪些部分待决定。
- **现行**：本主题当前采用的说明，注明未覆盖的范围。
- **历史**：已被替代或只用于回溯，文首说明原因与当前落点。

用短小文首说明加普通链接即可，不强制填元数据字段；标记只表达作者声明，不能证明内容正确。

## 维护贯穿任务

| 阶段 | 动作 |
|---|---|
| 探索 | 定位相关现行文档，指出不一致与未确认内容 |
| 设计 | 明确要新增或更新的文档，纳入相关单元与验收 |
| 施工 | 随行为变化更新受影响的说明，避免复制第二份规范 |
| 验收 | 核对文档与交付行为一致，确认长期结论已落位 |

不是每次代码改动都要写文档：有相关影响就维护，判断无影响就简短说明，不填「无提升」处置表。

## 发现与经验

- 未确认的发现留在任务详情，带依据与不确定性。
- 已确认且有长期复用价值的结论，整理进对应主题文档（指南、设计、故障处理说明都行）；任务详情保留摘要或引用。
- 不建无边界增长的经验总库；过程信息没有长期价值就不提升。

## 完成与保留

任务完成后保留原目录与两份文件，阶段改「完成」；正常任务列表默认省略已完成任务。产品不自动删除用户的工作材料，历史清理只在用户需要时做。
